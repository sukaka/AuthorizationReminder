# 管理员结果中心适配方案

## 目标

把“管理员结果中心”适配到 4 种主要上下文：

1. 桌面大屏：高效筛选、批量浏览、连续审阅
2. 平板：列表与详情切换自然，支持触控
3. 手机：快速查一条结果、看卷面、看考生记录
4. 打印：单次考试详情可直接打印成纸质报表

## 当前源上下文

这套界面目前默认是桌面后台表格思路，核心假设是：

- 左侧有固定侧边栏
- 中间是宽表
- 用户用鼠标操作
- “历史详情”可以直接复用考试页

这套假设对管理员结果中心不够。

问题在于：

- 桌面虽然能放表格，但没有形成“列表 + 详情”的管理结构
- 平板和手机下，宽表会迅速失效
- 结果详情是长内容，不适合继续塞回考试页

## 目标上下文与适配原则

### 桌面

- 使用场景：长时间审阅、连续打开多份结果、对比多个考生
- 输入方式：鼠标 + 键盘
- 目标：少跳转、少丢上下文、更多信息同时可见

### 平板

- 使用场景：会议、巡查、分屏查看
- 输入方式：触控为主，偶尔键盘
- 目标：保留列表与详情关系，但避免三栏拥挤

### 手机

- 使用场景：临时查某个考生、快速看分数或卷面
- 输入方式：单手触控
- 目标：先筛选，后展开；减少一次性信息量

### 打印

- 使用场景：归档、签字、线下复盘
- 目标：一份单次考试详情能直接打印，不带导航和无关操作

## 总体结构

统一使用两层模型：

1. 结果列表页
2. 结果详情页

考生详情页作为列表页的次级入口，不与结果详情混用。

不要在任何端继续复用答题页来展示历史结果。

## 桌面适配

### 推荐布局

采用 `摘要 + 列表 + 详情` 的 2.5 层结构。

- 顶部：筛选与摘要
- 左侧主区域：结果列表
- 右侧详情侧栏：当前选中结果的摘要版

当用户点击 `查看卷面` 时：

- 默认进入独立详情页
- 或先在右侧详情侧栏预览，再点“展开完整卷面”

### 桌面信息层级

顶部固定区域：

- 考生筛选
- 试卷筛选
- 通过状态
- 时间范围
- 是否最终成绩
- 当前筛选摘要

中间主表：

- 考生
- 试卷
- 考试时间
- 分数
- 是否通过
- 用时
- 第几次考试
- 操作

右侧预览栏：

- 本次分数
- 题型正确率
- 错题数
- 快捷操作
  - 查看卷面
  - 查看考生记录
  - 打印报表

### 桌面交互

- 支持行选中高亮
- 支持键盘上下切换结果
- 支持回车打开卷面详情
- 支持 `Esc` 关闭右侧预览栏

### 为什么这样适合桌面

- 管理员能连续浏览，不需要频繁来回跳
- 保留列表上下文
- 右侧预览能减少误点和重复打开

## 平板适配

### 推荐布局

使用 `两段式 master-detail`：

- 纵向：顶部筛选，下面结果列表
- 横向：左侧列表，右侧详情

根据方向切换：

- 竖屏：列表优先，详情全屏进入
- 横屏：列表与详情并排

### 平板规则

- 顶部摘要卡改成 2 列，不保留过多指标
- 筛选器默认折叠成“筛选”按钮，点开是抽屉
- 结果详情可以是右侧面板，也可以是全屏页

### 平板交互

- 所有操作按钮保持 44px 以上触控尺寸
- 不依赖 hover
- 行点击直接进入详情
- 详情页顶部提供明显返回

### 为什么这样适合平板

- 比桌面更适合少列信息
- 比手机能多留一点对比空间
- 横竖屏都不会破坏信息结构

## 手机适配

### 推荐布局

使用 `单列列表 + 全屏详情`。

手机端不要硬保留宽表，也不要强行并排。

顺序改成：

1. 顶部标题
2. 筛选按钮
3. 摘要数字条
4. 结果卡片列表

详情页是单独页面。

### 手机上的结果列表

每条结果改成卡片，而不是表格行。

卡片结构：

- 第一行：考生 / 分数 / 通过状态
- 第二行：试卷名称
- 第三行：考试时间 / 用时 / 第几次考试
- 底部操作：
  - 查看卷面
  - 查看考生记录

### 手机上的筛选

筛选改成顶部 `筛选` 按钮，打开底部抽屉或全屏筛选页。

抽屉里包含：

- 考生
- 试卷
- 时间范围
- 是否通过
- 是否最终成绩

底部固定操作：

- 应用筛选
- 清空筛选

### 手机上的详情页

详情页分三段：

- 顶部概览
- 报表摘要
- 逐题卷面

逐题卷面不要一次展开所有解析，改成折叠卡片：

- 题干
- 用户答案
- 正确/错误
- 点击展开标准答案与解析

### 为什么这样适合手机

- 保证任务最短路径明确
- 避免横向滚动
- 单手可操作

## 打印适配

### 打印对象

只适配 `单次考试详情页`，不适配结果列表页。

### 打印结构

- 页眉：
  - 考生
  - 试卷
  - 分数
  - 时间
- 摘要区：
  - 单选正确率
  - 多选正确率
  - 判断正确率
  - 错题数
- 卷面明细：
  - 题号
  - 题干
  - 用户答案
  - 标准答案
  - 是否正确
  - 解析
- 页脚：
  - 打印时间
  - 页码

### 打印规则

- 隐藏侧边栏、导航、按钮、筛选器
- 去掉彩色背景和装饰
- 分页点放在题目之间，不把一题拆开

## 断点建议

- 手机：`320px - 767px`
- 平板：`768px - 1023px`
- 桌面：`1024px+`
- 宽桌面：`1440px+`

推荐使用内容驱动断点：

- 当结果表列数开始挤压时，就切换成卡片或 master-detail
- 当详情区不足以同时展示摘要和题目时，详情改全屏

## 组件级适配建议

### 1. 结果列表

- 桌面：表格
- 平板：简化表格或双列列表
- 手机：卡片列表

### 2. 筛选区

- 桌面：直接平铺
- 平板：折叠抽屉
- 手机：底部抽屉或全屏筛选页

### 3. 详情预览

- 桌面：右侧固定预览栏
- 平板：右侧面板或全屏
- 手机：只保留全屏详情

### 4. 报表摘要

- 桌面：4 到 6 个指标并列
- 平板：2 列栅格
- 手机：横向滚动摘要条或 2 列卡片

## 不该做的适配

- 不要在手机上保留完整宽表
- 不要把桌面 hover 交互照搬到触控端
- 不要把详情做成超长弹窗后再嵌套滚动
- 不要在手机上隐藏“查看卷面”这种核心动作
- 不要让手机用户先进入考试页，再绕到历史详情

## 推荐实现顺序

### 第一步

先做桌面和平板通用结构：

- 结果列表
- 独立详情页
- 基础筛选

### 第二步

再做手机卡片版：

- 单列结果卡片
- 全屏详情
- 底部筛选抽屉

### 第三步

最后做打印适配：

- 单次考试详情打印样式

## 验收标准

### 桌面

- 能在不离开列表上下文的前提下连续查看多条结果
- 详情信息不挤压表格

### 平板

- 竖屏和横屏都能正常完成：
  筛选 -> 查看结果 -> 返回列表

### 手机

- 无横向滚动
- 所有主要按钮触控区域 >= 44px
- 用户可单手完成：
  打开筛选 -> 进入结果 -> 返回列表

### 打印

- 单次结果详情打印后可直接归档
- 无导航、无按钮、无截断题目

## 一句话总结

管理员结果中心不要只做“桌面宽表缩小版”，而要明确分成：

- 桌面：高效审阅
- 平板：列表与详情切换
- 手机：卡片与全屏详情
- 打印：单次结果报表
