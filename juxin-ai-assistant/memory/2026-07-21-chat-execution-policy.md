# 2026-07-21 聊天自动分流

## 用户目标

用户只提供问题。PPT 和长报告默认在后台可靠执行，普通短问答保持前台流式输出；后台任务显示真实进度，完成后通知并可加载完整结果，不能把后台任务伪装成逐字流式响应。

## 已实现决策

- 服务端是执行模式的唯一决策方，聊天准备接口返回 `foreground` 或 `background` 及可解释原因。
- PPT 创建和调整由既有 Dashi PPT 意图识别结果触发后台模式；长报告和正式材料生成由独立、可测试的执行策略判断。
- 教程、说明和简短摘要保持前台模式，避免关键词误判。
- 前端移除手动“后台处理”选项；Web 服务器模型按返回模式执行，本地密钥模式保持前台执行。
- 后台任务复用既有任务租约、状态、进度和会话结果，不增加第二套执行状态机。
- 任务完成时提供通知和“查看结果”，任务托盘仍保留完整进度与恢复入口。

## 验证结果

- 后端执行策略、普通聊天、长报告分流、PPT 创建/调整和长任务：14 项测试通过。
- 前端聊天交互与样式：60 项测试通过。
- 桌面端 TypeScript 类型检查通过。
