# 2026-07-21 聊天内大师 PPT 生成与调整

## 用户目标

用户只提供问题，聚信 AI 助手在普通聊天中自动调用大师 PPT Skill，在服务器生成真实 PPTX；后续聊天可以继续调整同一份演示稿。导出必须使用大师 PPT 完整运行时中的 `html-deck-to-pptx`，不能只返回大纲或伪造文件。

## 原因定位

此前大师 PPT 只接入能力中心的显式 Skill 运行入口，普通聊天仍由通用模型直接回答，因此模型会声明“不能生成可下载的 PPTX”。问题不是导出引擎不能运行，而是聊天完成链路没有调用已安装的 Skill。

## 已实现

- 新增聊天 PPT 意图识别，区分创建、修改和普通 PPT 知识问答。
- 聊天准备阶段注入服务器真实生成约束，避免模型拒绝生成 PPTX。
- 聊天完成阶段把模型结果转换为受校验的 Dashi `goal_spec`，通过统一 `SkillRunner` 调用完整运行时。
- 返回可下载、浏览器可编辑的 HTML 和真实 PPTX 两种聊天附件。
- 同一用户、同一聊天中的修改请求读取最近一次成功计划并生成新版本；跨用户和跨会话不可见。
- “把第二页改成……”等中文页码调整可以识别；旧版本不覆盖。
- 内容页采用不重复的 Dashi 版式，单次最多生成 10 页。
- 前端增加 HTML 附件类型和“下载后可编辑”提示。

## 验证结果

- 后端相关测试：54 项通过。
- 桌面端 TypeScript 类型检查：通过。
- Git 差异格式检查：通过。
- 使用本地安装的完整上游运行时完成 10 页真实导出：HTML 约 465 KB，PPTX 约 10 MB。
- PPTX 压缩包完整性检查通过，10 个页面文件均可读取。

## 部署状态与下一步

代码已在本地完成，但本次未部署远程预发布服务器，也未提交、推送或升级版本号。服务器需要按 `docs/dashi-ppt-runtime-install.md` 安装锁定的上游运行时，设置 `DASHI_PPT_RUNTIME_ROOT`，安装 Node.js/npm 与 Chrome/Chromium，重建 API 后进行真实登录冒烟测试。

建议冒烟流程：聊天输入“帮我做一份年度经营汇报 PPT” → 确认返回 HTML/PPTX → 输入“把第二页改成风险分析” → 确认返回新版本且旧版本仍可下载。

## 预发布构建报错修复

预发布构建失败的直接原因是 Python 基础镜像默认指向需要认证的腾讯云仓库，拉取时返回 `401 Unauthorized`，并连带取消依赖服务构建。已把根 Compose 和 AI 助手 Dockerfile 的默认值统一改为公开的 `python:3.12-slim`，同时保留 `PYTHON_BASE_IMAGE` 环境变量供有私库凭据的部署环境显式覆盖。新增配置回归检查，防止默认值再次变回需要认证的仓库。

修复后验证：公开镜像清单可从 Docker Hub 正常读取，并包含 Linux amd64/arm64；基础镜像回归检查、Dockerfile 镜像源一致性检查、Dashi PPT Compose 配置校验及 Git 差异检查均通过。本次交付目标是随 5.0 主线的下一功能版本提交并推送；尚未代替用户操作远程服务器部署。
