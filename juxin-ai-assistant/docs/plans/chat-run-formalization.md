# 5.0 聊天 Run 上下文正式化计划

## 目标

将已验证的聊天 Run 原型逐步落到正式 `ChatPage`，让用户在真实聊天过程中能看见当前任务的目标、阶段、活动、引用来源和可交付成果。

## 已完成范围

- 复用现有 `taskProgress`、`lastRunId`、消息引用和生成文件，在正式聊天页增加 Run 上下文侧栏，并提供计划、活动、来源、成果四个只读视图。
- 聊天准备接口和历史会话详情统一返回 `task_state.run_id`；历史会话按用户和会话范围恢复最新 Run。
- Run 列表支持按 `conversation_id` 过滤，后续任务中心或侧栏查询不会混入其他会话的任务。
- 停止生成时同时取消本地模型请求和统一 Run；统一 Run 已结束时取消请求保持容错，不影响聊天页状态。
- 切换、新建或彻底删除会话时清理旧 Run 上下文，避免跨会话串任务。
- 为服务层和正式聊天页增加恢复、取消和回归测试。

## 暂不纳入

- Steer/Queue 的服务端语义和并发控制。
- 多 Worker、恢复协议和持久化 Run 事件流。
- 版本号、提交和推送操作。

## 验收标准

1. 有聊天内容时，正式聊天页显示 Run 上下文侧栏；无任务数据时显示明确的空状态。
2. 计划页显示任务目标、当前阶段、下一步和阶段轨迹。
3. 活动页显示工具调用及结果；来源页汇总任务来源和回答引用；成果页展示可下载文件。
4. 侧栏不改变现有发送、停止、加载历史会话和导出行为。
5. 在 `apps/desktop` 目录执行 `npm run typecheck`、`npm run test -- --run tests/chat-run-context.test.tsx tests/chat-page.test.tsx` 和 `npm run build` 通过。

## 下一步

以现有 Run 状态机、事件表和租约机制为基础，先补齐 Queue/Steer 的服务端语义和恢复协议，再接入前端操作；避免在前端先造出无法兑现的状态。
