# 聚信 AI 助手 6.0 / 7.0 产品与研发计划

> 文档版本：1.0
> 编制日期：2026-07-12
> 规划范围：聚信 AI 助手 6.0、7.0
> 文档用途：产品立项、技术评审、研发排期、资源协调、验收与发布决策

---

## 1. 规划摘要

聚信 AI 助手未来两个大版本分两步完成产品升级：

- **6.0：企业任务工作台。** 从“回答问题”升级为“理解任务、查找资料、执行步骤、生成成果、完成复核”的企业工作助手。
- **7.0：企业 Agent Hub。** 从“单一 AI 助手”升级为“能够连接、调度和治理飞书、企业微信、Kimi、即梦及企业内部 Agent 的多智能体协作平台”。

两个版本的关系如下：

```text
5.x：知识问答与资料管理
  ↓
6.0：任务执行 + 成果生成 + 可信交付
  ↓
7.0：外部 Agent 接入 + 智能调度 + 跨平台协作
```

核心原则：

1. 6.0 先把任务、权限、引用、成果、审计和后台执行做扎实。
2. 7.0 基于 6.0 的任务底座连接外部 Agent，不重复建设任务系统。
3. 用户始终面对聚信 AI 助手，第三方 Agent 作为受控的专业能力被调用。
4. 所有资料访问、外部发送和 Agent 调用均遵循统一身份、权限和审计规则。
5. 简单问题保持快速，复杂任务进入后台执行，不让所有请求都走高成本工作流。

## 2. 总体业务目标

### 2.1 用户价值

用户可以在一个入口完成以下工作：

- 查询公司制度、产品资料、项目文件和个人资料。
- 跨多个文档进行汇总、对比、核验和引用。
- 将自然语言需求转成可执行任务。
- 生成 Word、PPT、Excel、PDF 和 Markdown 成果。
- 查看任务进度，切换页面后任务继续执行。
- 在飞书、企业微信或 Web 中发起、查看和继续同一任务。
- 调用专业 Agent 完成图片、视频、长文档分析和消息发送。

### 2.2 管理价值

管理员可以：

- 管理资料版本、分类、权限、有效期和检索状态。
- 管理任务模板、成果模板和审核流程。
- 查看回答质量、引用质量、任务成功率和响应性能。
- 注册、授权、停用和监控外部 Agent。
- 控制敏感资料是否允许发送到外部厂商。
- 查看调用成本、数据流向和完整审计记录。

### 2.3 产品价值

- 从通用聊天工具转变为可落地的企业生产力平台。
- 形成知识库、工作流、成果模板和 Agent 生态的持续积累。
- 用权限、审计、可信引用和数据出域控制形成企业级差异化。
- 降低后续接入新模型、新 Agent 和新业务系统的开发成本。

# 第一部分：6.0 企业任务工作台

## 3. 6.0 版本定位

### 3.1 版本主题

**从“能回答”升级为“能完成”。**

6.0 的核心不是增加更多聊天按钮，而是让用户把一项完整工作交给 AI。AI 能够理解目标、选择资料、拆分步骤、执行任务、生成成果、检查质量，并将最终结果交付给用户。

### 3.2 典型使用场景

1. 根据建设方案和管理员手册生成客户培训 PPT，并附讲师讲稿。
2. 汇总多份项目资料，生成项目验收材料清单。
3. 根据测试记录生成测试报告和缺陷分析。
4. 对比产品方案不同版本，输出差异说明。
5. 根据会议记录生成纪要、待办、责任人和时间节点。
6. 根据制度文件回答问题，逐条显示原文依据。
7. 根据 Excel 数据生成分析结论、图表和汇报材料。
8. 根据公司模板生成周报、方案、通知和总结。

### 3.3 6.0 不做的内容

- 不允许 AI 未经确认直接对外发送正式文件。
- 不允许普通用户绕过权限读取其他部门或项目资料。
- 不允许 AI 自主修改生产代码、系统配置和正式知识。
- 不追求无边界自主 Agent，所有执行步骤均受预算、权限和流程约束。
- 不在 6.0 大规模接入第三方 Agent；只预留统一接口并完成少量内部试点。

## 4. 6.0 功能范围

### 4.1 统一任务中心

每次用户操作都形成独立任务，任务必须包含：

- 全局任务 ID
- 发起用户和组织身份
- 所属会话
- 用户目标
- 使用的资料范围
- 当前步骤和进度
- 生成中的草稿
- 最终成果
- 引用与证据
- 执行日志和错误信息
- 创建、完成和更新时间

任务状态建议统一为：

```text
草稿 → 排队中 → 正在执行 → 等待确认 → 已完成
                    ├→ 已暂停
                    ├→ 重试中
                    ├→ 已取消
                    └→ 执行失败
```

前端要求：

- A 任务的消息和结果只能出现在 A 任务。
- 切换到 B 任务不影响 A 任务后台执行。
- 刷新页面后能恢复任务状态和流式进度。
- 支持取消、重试、复制任务和从失败步骤继续。
- 长任务完成后在站内提醒用户。

### 4.2 任务规划与执行

系统根据复杂度选择三种执行路径：

| 类型 | 场景 | 执行方式 |
|---|---|---|
| 快速问答 | 简单问答、润色、解释 | 单次模型调用或直接规则回复 |
| 知识任务 | 资料查询、跨文档汇总 | 检索、生成、引用校验 |
| 成果任务 | 报告、PPT、分析、方案 | 规划、执行、复核、成果生成 |

复杂任务执行步骤：

1. 识别目标、受众、成果类型和完成标准。
2. 判断需要哪些资料和权限。
3. 生成用户可见的简要执行计划。
4. 按步骤执行，并持续保存 checkpoint。
5. 生成结构化成果草稿。
6. 执行事实、引用、格式和敏感信息检查。
7. 必要时等待用户或审核人确认。
8. 生成最终成果并归档。

### 4.3 多资料深度检索

检索策略按任务类型动态调整：

| 场景 | 建议召回片段 | 上限 | 处理方式 |
|---|---:|---:|---|
| 精准事实查询 | 12 | 16 | 优先高相关度和原文定位 |
| 多资料汇总 | 16～20 | 24 | 提升来源覆盖度并去重 |
| 跨版本对比 | 每个版本 8～12 | 24 | 按文档分组后比较 |
| 复杂成果任务 | 分阶段召回 | 单阶段 24 | 先目录检索，再章节检索 |

必须具备：

- 关键词、语义和目录混合检索。
- 查询扩展、同义词和产品简称识别。
- 多文档覆盖度控制，避免只命中一个文档。
- 相似片段去重和章节连续性补全。
- 二次检索：第一轮证据不足时自动改写问题继续查找。
- 文档权限在检索前过滤，而不是生成后再过滤。
- 所有关键结论绑定真实引用胶囊。
- 点击引用可定位文件、版本、章节、页码和原文片段。
- 区分“资料原文”“基于资料推断”和“通用建议”。

### 4.4 文档版本管理

在现有同名提示、重命名和归档能力上增加：

- 同名上传时选择“创建独立资料”或“更新现有资料”。
- 同一资料建立版本时间线，如 v1、v2、v3。
- 支持版本说明、上传人、更新时间和变更原因。
- 自动生成版本差异摘要。
- 指定当前生效版本和参与检索版本。
- 历史版本默认不参与检索，但可以查看、比较和恢复。
- 引用必须记录具体版本，防止结果随版本变化失去依据。
- 检测重复文件、近似文件和疑似过期资料。

### 4.5 智能资料整理

上传完成后自动建议：

- 一级分类和二级分类
- 文档类型
- 标签与摘要
- 产品、项目、客户和版本信息
- 权限范围
- 有效期和复核时间
- 是否属于重复资料
- 是否包含敏感信息
- 是否适合进入正式知识库

自动建议不能直接改变正式资料，管理员确认后生效。

### 4.6 成果生成中心

支持以下成果类型：

| 成果 | 典型用途 | 主要能力 |
|---|---|---|
| Word | 方案、报告、制度、总结 | 公司模板、目录、页眉页脚、引用 |
| PPT | 培训、宣讲、汇报 | 提纲、版式、讲稿、图片、引用页 |
| Excel | 清单、台账、分析 | 表格生成、公式、统计和图表 |
| PDF | 正式交付 | 固化版式、水印和权限提示 |
| Markdown | 技术文档、知识文章 | 结构化内容、代码块和表格 |
| 文本 | 邮件、通知、消息 | 多种语气、受众和长度 |

生成流程：

1. 选择成果类型。
2. 选择模板或从空白开始。
3. 确认资料范围、受众、篇幅和风格。
4. AI 生成提纲，用户可先确认。
5. 后台生成完整成果。
6. 在线预览和局部修改。
7. 质量检查通过后导出。
8. 保存为工作成果或模板。

### 4.7 企业模板中心

模板应同时保存：

- 模板名称和适用场景
- 成果格式
- 固定章节结构
- 所需输入字段
- 默认知识库范围
- Prompt 版本
- 公司样式和品牌资产
- 审核流程
- 可使用部门和人员
- 创建人、版本和变更记录

首批模板建议：

- 项目周报
- 测试计划与测试报告
- 缺陷分析报告
- 项目验收材料清单
- 客户培训 PPT
- 产品介绍 PPT
- 会议纪要
- 故障分析报告
- 等保整改建议
- 产品方案和对比报告

### 4.8 AI 质量审核

成果交付前执行四类检查：

1. **事实检查**：结论是否有资料依据，数字和名称是否一致。
2. **引用检查**：引用是否真实存在，是否确实支持对应结论。
3. **格式检查**：章节、模板、表格、标题和文件格式是否完整。
4. **风险检查**：是否包含敏感信息、过期内容、越权资料或对外承诺。

检查结果分为：

- 通过：可以直接交付。
- 建议修改：用户可以继续，但需看到问题提示。
- 必须复核：需要人工确认后才能导出或发送。
- 拒绝交付：存在权限、敏感数据或重大事实问题。

### 4.9 岗位助手

6.0 提供统一底座上的岗位化入口：

- 销售助手
- 售前助手
- 测试助手
- 项目助手
- 运维助手
- 培训助手
- 行政人事助手
- 管理助手

岗位助手只改变默认模板、工具、知识范围和交互引导，不复制建设独立系统。

### 4.10 管理与运营中心

管理员应能查看：

- 无答案问题和低置信回答
- 热点问题和高频任务
- 文档命中次数和引用次数
- 长期未使用、解析失败和疑似过期资料
- 资料重复率和版本分布
- 任务成功率、失败率和平均耗时
- 普通问答首字时间和完整响应时间
- 用户反馈和人工修改率
- 模型调用量与成本
- Prompt、模板和工作流版本效果

## 5. 6.0 技术架构

### 5.1 核心服务

```text
Web / Desktop / Mobile
        │
API Gateway、身份认证与权限
        │
Task Service ───── Event Stream
        │
Workflow Runtime
├── Intent Router
├── Knowledge Researcher
├── Writer
├── Reviewer
└── Artifact Generator
        │
Tool Registry / Model Gateway
        │
MySQL + Redis + Vector Index + Object Storage
```

### 5.2 后台任务与消息隔离

- 任务、会话、消息和流式事件必须同时携带 `task_id`。
- 前端仅订阅当前任务的事件，其他任务只更新未读状态。
- 后端事件发布前校验用户和任务归属。
- 每个任务按步骤保存 checkpoint，进程重启后可以恢复。
- 重试采用幂等键，避免重复生成成果或重复发送通知。
- 长任务由独立 worker 执行，Web 请求不等待完整任务结束。

### 5.3 缓存与性能

缓存分层：

- 浏览器缓存：静态资源和非敏感界面配置。
- 应用内存缓存：字典、模型配置、资料目录等短期数据。
- Redis：会话、任务状态、分布式锁、热点问题和限流。
- 检索缓存：规范化问题到候选片段 ID，权限发生变化时失效。
- Embedding 缓存：相同文本不重复向量化。
- 文档摘要缓存：按文件版本保存章节摘要。
- 成果中间态缓存：断点恢复和局部重新生成。

性能目标：

| 场景 | 目标 |
|---|---:|
| FAQ/固定回复 P95 | 1 秒内 |
| 普通问答首字 P95 | 3 秒内 |
| 知识问答首字 P95 | 8 秒内 |
| 简单知识回答完成 P95 | 30 秒内 |
| 复杂任务状态确认 | 2 秒内返回任务 ID |
| 页面切换后的任务恢复 | 2 秒内 |

### 5.4 数据模型

建议新增或统一：

- `ai_tasks`：任务主表
- `ai_task_steps`：执行步骤与 checkpoint
- `ai_task_events`：流式事件
- `ai_artifacts`：成果文件和版本
- `ai_artifact_reviews`：成果审核
- `knowledge_file_versions`：资料版本
- `knowledge_citations`：引用和原文定位
- `workflow_templates`：工作流模板
- `artifact_templates`：成果模板
- `quality_evaluations`：质量检查结果
- `model_usage_records`：模型用量和成本

### 5.5 安全要求

- 所有检索先做权限过滤。
- 成果继承来源资料中最严格的权限范围。
- 下载、预览、导出和分享都记录审计日志。
- 敏感任务禁止进入无授权模型通道。
- Prompt、模型返回和日志不得记录明文密钥。
- 上传文件执行类型、大小、恶意内容和文件名安全检查。

## 6. 6.0 研发阶段与里程碑

建议周期：**24～30 周**，按团队规模可并行压缩。

### 阶段 0：基线治理（2 周）

- 固化现有 5.x 功能和数据迁移基线。
- 清理阻断性缺陷和测试不稳定问题。
- 建立前后端、数据库迁移和部署流水线。
- 定义任务、成果、引用和事件统一协议。

验收：核心测试全绿，协议通过技术评审，具备一键回滚能力。

### 阶段 1：任务底座（4～5 周）

- 建设全局任务 ID、任务状态机和任务中心。
- 后台 worker、队列、取消、重试和 checkpoint。
- 修复跨任务消息串线和页面切换状态问题。
- 接入任务进度和站内通知。

验收：并发创建 100 个任务不串线；服务重启后可恢复未完成任务。

### 阶段 2：深度检索与可信引用（4～5 周）

- 混合检索、动态召回、跨文档覆盖和二次检索。
- 引用胶囊、原文定位、版本绑定和引用检查。
- 无依据拒答、资料冲突提示和推断标记。

验收：标准评测集中引用准确率不低于 95%，无依据正确拒答率不低于 98%。

### 阶段 3：成果生成（5～6 周）

- Word、PPT、Excel、PDF 和 Markdown 生成。
- 成果中心、预览、版本、下载和归档。
- 首批企业模板和品牌样式。
- 提纲确认和局部重新生成。

验收：至少 10 个标准模板可稳定生成；关键格式通过人工验收。

### 阶段 4：质量审核与资料版本（4～5 周）

- 事实、引用、格式和风险检查。
- 同名更新、版本时间线、差异比较和有效版本。
- 重复和过期资料检测。
- 人工审核节点。

验收：正式成果均有质量报告；旧版本不会默认参与检索。

### 阶段 5：运营、灰度与发布（3～4 周）

- 管理运营看板。
- 性能压测、安全测试和数据迁移演练。
- 选择 2～3 个部门灰度。
- 修复灰度问题并分批发布。

验收：连续两周达到核心指标，无高危安全问题和阻断性故障。

# 第二部分：7.0 企业 Agent Hub

## 8. 7.0 版本定位

### 8.1 版本主题

**从“一个 AI 助手”升级为“多 Agent 协同平台”。**

聚信 AI 助手作为总入口和总调度者，根据任务安全调用飞书、企业微信、Kimi、即梦、企业内部 Agent 及其他专业能力。用户无需在多个平台之间复制资料和结果。

### 8.2 接入对象分类

| 类型 | 示例 | 平台中的角色 |
|---|---|---|
| 协作渠道 | 飞书、企业微信 | 接收任务、发送消息、文件和通知 |
| 外部智能体/模型 | Kimi 等 | 长文档分析、写作、推理等能力 |
| 内容生成服务 | 即梦等 | 图片、视频和视觉素材生成 |
| 企业内部 Agent | 运维、项目、培训 Agent | 执行专业业务任务 |
| 业务系统 | OA、CRM、工单、项目系统 | 查询和更新业务数据 |
| 通用工具服务 | 搜索、邮件、日历、存储 | 完成具体动作 |

### 8.3 7.0 不做的内容

- 不允许第三方 Agent 直接获取全部公司资料。
- 不把厂商凭证交给前端或最终用户。
- 不允许 Agent 在无审批情况下对外发送高风险内容。
- 不承诺所有厂商接口完全一致，统一的是平台内部能力协议。
- 不允许一个外部 Agent 的故障拖垮整个任务系统。

## 9. 7.0 功能范围

### 9.1 Agent 接入中心

管理员可以完成：

- 新增、测试、启用、停用和删除连接。
- 配置 API 地址、认证方式、密钥和回调地址。
- 配置可用人员、部门、岗位和任务类型。
- 配置超时、并发、每日限额和预算。
- 查看健康状态、最近调用和错误原因。
- 配置备用 Agent 和降级策略。

凭证要求：

- 加密存储。
- 页面只显示掩码。
- 支持定期轮换和失效时间。
- 读取和修改均记录审计。
- 不进入 Prompt、普通日志和前端响应。

### 9.2 统一 Agent 能力协议

每个 Agent 注册以下信息：

- Agent ID、名称、厂商和版本
- 能力标签
- 输入、输出和附件类型
- 参数 Schema
- 是否支持流式响应
- 是否支持异步任务和回调
- 超时、并发和重试策略
- 数据出域等级
- 适用场景和禁止场景
- 预计耗时和成本
- 健康状态和服务等级

统一调用对象示例：

```json
{
  "task_id": "task-uuid",
  "capability": "image.generate",
  "input": {
    "prompt": "生成产品宣讲封面",
    "aspect_ratio": "16:9"
  },
  "data_policy": "external_allowed_after_masking",
  "callback": "internal-task-event-channel"
}
```

### 9.3 智能路由与选择

选择 Agent 时综合考虑：

- 用户明确指定
- 能力是否匹配
- 资料是否允许出域
- 用户是否有调用权限
- 当前健康度和响应时间
- 调用成本和预算
- 历史任务成功率
- 输出质量评分
- 是否需要中文、长文本、图片或视频能力

路由顺序：

1. 权限和数据策略过滤不可用 Agent。
2. 用户指定且可用时优先使用指定 Agent。
3. 根据能力、质量、时间和成本评分选择。
4. 主 Agent 失败时按策略切换备用 Agent。
5. 所有选择原因写入可审计记录。

### 9.4 多 Agent 工作流

支持：

- 串行执行
- 并行执行
- 条件分支
- 人工确认
- 定时等待
- 失败重试
- 备用 Agent 切换
- 补偿操作
- 子任务合并

示例：

```text
用户提出客户宣讲任务
  → 聚信知识助手检索产品资料
  → 写作 Agent 生成宣讲结构
  ├→ PPT Agent 生成课件
  └→ 即梦生成封面和宣传图
  → 审核 Agent 检查事实、引用和品牌规范
  → 负责人确认
  → 飞书 Agent 发送到项目群
  → 成果归档并记录审计
```

### 9.5 飞书接入

首期能力：

- 私聊和群聊中发起 AI 任务。
- 根据用户身份访问授权资料。
- 返回流式进度、引用和成果文件。
- 将成果发送到指定群或人员。
- 读取授权范围内的文档、日历、任务和消息。
- 创建待办、日程和通知。
- Web 与飞书任务互相跳转。

必须处理：

- 飞书用户与系统用户绑定。
- 群聊机器人权限和资料权限分离。
- 群聊问题不能自动使用提问者的私人资料。
- 消息回复绑定原消息、群聊和任务 ID。

### 9.6 企业微信接入

首期能力：

- 企业内部消息问答和任务发起。
- 群聊通知和成果发送。
- 员工身份映射和部门权限同步。
- 审批结果、任务完成和异常提醒。
- 在明确授权后支持客户沟通内容草拟。

对外部联系人发送内容必须增加人工确认，不允许默认自动发送。

### 9.7 Kimi 等外部智能体接入

主要用途：

- 长文档分析
- 复杂内容整理
- 特定模型擅长的写作或推理任务
- 主模型不可用时的备用通道

平台必须做到：

- 调用前进行权限和数据出域判断。
- 必要时只发送脱敏摘要，不发送原始文件。
- 记录实际发送的数据范围和返回结果。
- 允许管理员按部门关闭外部模型。
- 不把外部结果直接作为正式结论，仍经过引用与质量检查。

### 9.8 即梦等视觉能力接入

主要用途：

- PPT 封面和插图
- 产品宣传图
- 培训素材
- 短视频和动态内容
- 工作成果视觉优化

管理能力：

- 公司品牌词、禁用词和视觉规范。
- 生成尺寸、比例、风格和数量限制。
- 图片和视频版权及用途提示。
- 生成记录、提示词、审核状态和成果归档。
- 敏感人物、客户标识和未授权商标检查。

### 9.9 跨平台任务同步

一个任务可以从任意入口发起，并在其他入口继续：

- 飞书发起，Web 查看完整过程。
- Web 生成，企业微信收到完成提醒。
- 管理员在 Web 审核，结果返回原飞书群。
- 移动端取消任务，后台立即停止后续步骤。

所有入口共享：

- 同一任务 ID
- 同一权限快照
- 同一成果和引用
- 同一审计记录
- 各渠道独立的消息定位信息

### 9.10 身份、权限与数据出域

统一身份模型：

```text
系统用户
├── 飞书身份
├── 企业微信身份
├── 部门、岗位和角色
├── 可访问知识库
├── 可调用 Agent
├── 可使用业务工具
└── 可发送目标范围
```

数据策略建议分级：

| 等级 | 处理规则 |
|---|---|
| L0 公开 | 可发送至授权外部 Agent |
| L1 内部 | 仅发送必要片段并记录审计 |
| L2 敏感 | 脱敏后且经用户确认方可出域 |
| L3 机密 | 仅允许本地模型和内部 Agent |

### 9.11 Agent 审计与成本中心

每次调用记录：

- 发起用户和入口
- 任务、步骤和 Agent
- 调用原因和路由原因
- 输入数据分类及资料 ID
- 是否出域和是否脱敏
- 请求时间、响应时间和状态
- Token、次数或厂商计费信息
- 返回成果
- 人工审批结果
- 后续发送目标

运营指标：

- Agent 调用量、成功率和 P95 耗时
- 单任务成本和月度成本
- 降级次数和故障率
- 用户满意度和人工修改率
- 不同 Agent 在同类任务中的效果对比
- 各部门预算使用情况

### 9.12 Agent 市场与低代码编排

7.0 后期提供内部 Agent 市场：

- 浏览和搜索 Agent。
- 查看能力、权限、成本和适用场景。
- 管理员安装并授权。
- 用户收藏常用 Agent 或工作流。
- 开发者按规范发布内部 Agent。

低代码流程设计器支持：

```text
触发器 → 资料检索 → Agent 调用 → 条件判断
       → 人工审核 → 文件生成 → 消息发送 → 归档
```

### 10.1 Agent Gateway 要求

- 对内提供统一同步、流式和异步调用接口。
- 对外适配不同厂商认证、参数和回调方式。
- 支持超时、限流、重试、熔断和降级。
- 支持能力发现、版本和健康检查。
- 统一错误码，不直接把厂商错误暴露给用户。
- 调用前执行策略，调用后记录审计和计费。

### 10.2 稳定性设计

- 每个厂商连接使用独立连接池和限流器。
- 外部调用全部设置明确超时。
- 连续失败触发熔断，避免拖慢主系统。
- 异步回调需验签、防重放和幂等。
- 外部 Agent 不可用时给出降级方案，不无限重试。
- 关键发送动作使用事务消息或发件箱模式，避免状态不一致。

## 17. 风险与应对

| 风险 | 影响 | 应对措施 |
|---|---|---|
| 任务复杂度过高 | 延期、稳定性下降 | 分阶段交付，先确定性工作流 |
| 检索仍有漏召回 | 回答不可信 | 混合检索、二次检索、评测集 |
| 成果格式不稳定 | 难以正式使用 | 模板化生成、渲染校验、人工复核 |
| 消息串任务 | 严重用户错误 | 全链路 task_id、事件权限和并发测试 |
| 外部服务不稳定 | 任务失败、延迟 | 超时、熔断、降级和备用 Agent |
| 敏感数据出域 | 安全与合规事故 | 数据分级、脱敏、审批和审计 |
| 厂商成本失控 | 运营成本上升 | 预算、限额、路由和成本看板 |
| 接口变化 | 连接器失效 | 适配层、版本管理和合约测试 |
| 权限模型过于复杂 | 越权或不可用 | 统一身份、默认拒绝、权限评测 |
| 用户不知道如何使用 | 使用率低 | 场景入口、模板、示例和岗位助手 |

## 19. 最终成功标准

6.0 成功的标志不是“聊天功能更多”，而是用户可以把真实工作交给 AI，并得到有依据、可编辑、可审核、可归档的成果。

7.0 成功的标志不是“接入厂商更多”，而是聚信 AI 助手能够在统一权限和安全治理下，稳定调度多个 Agent 完成跨平台任务，而用户不需要理解背后的厂商和接口差异。

最终产品形态应当是：

> 聚信 AI 助手负责理解用户、掌握企业知识和统筹任务；专业 Agent 负责发挥各自能力；企业平台负责权限、安全、审计和成果沉淀。
