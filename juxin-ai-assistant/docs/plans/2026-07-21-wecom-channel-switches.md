# 企业微信通道前台开关实施说明

## 目标

- 在管理中心的功能开关区域新增“企业微信”和“企业微信客服”两个独立开关。
- 开关只控制通道是否接收、处理和回复消息，不保存任何通道凭据。
- 保存开关后运行中的 API 立即读取新状态，不需要重启。
- `.env` 中的企业微信凭据发生变化后，必须重启 API 才能载入新值。

## 配置边界

企业微信通道从服务器环境读取 `WECOM_CORP_ID`、`WECOM_SECRET`、`WECOM_TOKEN`、`WECOM_ENCODING_AES_KEY` 和 `WECOM_AGENT_ID`。

企业微信客服通道从服务器环境读取 `WECOM_KF_CORP_ID`、`WECOM_KF_SECRET`、`WECOM_KF_TOKEN`、`WECOM_KF_ENCODING_AES_KEY` 和 `WECOM_KF_IDENTITY_HASH_SALT`，并要求启用 Redis。

前端和运行时开关接口只返回配置是否就绪以及缺失的环境变量名称，不返回环境变量值。启用配置不完整的通道时，接口拒绝保存并给出缺失项。

## 生效语义

1. 管理员保存开关后，API 将状态写入运行时特性开关文件。
2. webhook 和企业微信客服回复在每次请求时读取该文件，因此启停立即生效。
3. 通道关闭后，企业微信与企业微信客服入口返回通道停用，不再处理消息；企业微信客服也不再向外发送回复。
4. 修改 `.env` 后需重启 API；前台开关状态不会因为 API 重启而丢失。

## 验收标准

- 两个开关可以独立保存，并且请求体中只包含对应通道的布尔值。
- 开启或关闭企业微信后，真实 webhook 无需重启即可反映新状态。
- 企业微信客服的回复发送遵循前台开关，不再依赖旧的环境启用布尔值。
- 未配置完整凭据时无法开启通道。
- 前台、接口响应和日志中均不出现 App ID、Secret、Token、加密密钥或身份哈希盐的值。
