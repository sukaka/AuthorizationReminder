# 资料库外部访问与原文件外发控制计划

> 状态：功能已在当前 5.0 工作区实现并完成目标验证；暂不提交、推送或升级版本号，待 5.0 完成后再发布。

## 背景

公众号、小程序等外部渠道当前使用 `KnowledgeFile.external_public` 同时决定文档能否参与问答、能否出现在资料下载列表以及能否下载原文件。这样无法实现“允许 AI 根据文档回答，但禁止把原文件发给外部用户”。

## 目标与边界

- 保留 `external_public`，语义明确为“允许外部渠道检索并用于回答”。
- 新增 `external_download_allowed`，语义为“允许外部渠道发送或下载原文件”。
- 两项默认都为 `false`；历史数据迁移后原文件外发默认关闭。
- 外部下载必须同时满足 `external_public=true` 和 `external_download_allowed=true`。
- 关闭外部问答、关闭 RAG、归档、删除、重新送审或审核拒绝时，自动关闭原文件外发。
- 权限过滤必须发生在知识检索和文件查询阶段；不能先读取无权资料再在回答阶段拦截。
- 桌面管理端的内部预览、下载及现有公司/部门/项目权限不受影响。

## 权限矩阵

| 外部问答 | 原文件外发 | 外部渠道行为 |
|---|---|---|
| 关闭 | 关闭 | 不参与检索、不展示文件、不允许下载 |
| 开启 | 关闭 | 可以根据文档回答，但不展示或发送原文件 |
| 开启 | 开启 | 可以回答，也可以展示并发送原文件 |
| 关闭 | 开启 | 非法组合；前后端都拒绝并自动关闭原文件外发 |

## 管理端交互

- 在正式资料的编辑区显示“允许外部问答”和“允许发送原文件”两个开关。
- “允许发送原文件”依赖“允许外部问答”；父开关关闭时，子开关自动关闭并禁用。
- 文件卡显示“仅内部 / 外部可问”和“禁止外发 / 可发原件”状态。
- 普通员工只能查看状态，只有管理员可以修改。
- 新上传、审核通过和历史文档都默认两项关闭，必须由管理员逐份显式开放。

## 服务端控制顺序

1. 识别入口是否为公众号、小程序等外部渠道。
2. 在知识检索 SQL 中先过滤 `external_public=true`，再把片段交给模型。
3. 文件列表、下载令牌签发和令牌兑换均同时校验 `external_download_allowed=true`。
4. 删除、归档、停用 RAG、重新送审或审核拒绝时同时撤销两项外部权限。
5. 保留下载审计记录，记录访问者、文件、时间和结果，但不记录原文内容。

## 实施步骤

1. 先补后端失败测试，覆盖默认拒绝、管理员权限、依赖校验、级联关闭和外部下载过滤。
2. 新增数据库字段与迁移，并扩展 API Schema 和资料更新接口。
3. 将外部资料列表、下载令牌和最终下载查询改为双重权限过滤。
4. 在桌面端资料编辑区增加两个联动开关，并展示外部访问状态。
5. 补前端交互/API 测试，执行目标测试、类型检查、迁移检查和 `git diff --check`。
6. 5.0 稳定基线形成后再确定版本；若基线为 `5.0.x`，按功能优化规则发布为 `5.1.0`。当前不提交、不推送，避免把本功能与 5.0 未完成改动混合发布。

## 验收标准

- 未显式开放的文档无法被公众号/小程序检索，也无法通过直接请求下载。
- 只开放外部问答的文档可以形成回答，但外部资料列表、下载令牌和下载接口均不可获得原文件。
- 开放原文件外发前必须先开放外部问答，绕过前端直接调用 API 也会被拒绝。
- 管理员关闭外部问答后，已有下载权限立即失效；已签发但未使用的令牌也无法兑换文件。
- 内部桌面端既有检索、预览和下载行为不受影响。
- 历史 `external_public=true` 文档迁移后保持可回答，但原文件外发默认关闭，由管理员重新确认。
