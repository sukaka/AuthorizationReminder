# 左侧导航归类实施计划

## 目标

将桌面端左侧扁平菜单收敛为稳定的工作域导航，降低首屏认知负担，同时保留现有页面、角色权限和业务流程。

## 范围

- 主导航固定为“对话、项目、任务与交付、AI 能力、知识与学习、企业洞察”六个一级入口；无企业查看权限时隐藏“企业洞察”。
- 将原有二级业务页面放到工作区顶部页签中：
  - 任务与交付：我的任务、专业任务、成果中心、工作成果。
  - AI 能力：助手模式、工作流、能力中心、Agent 市场。
  - 知识与学习：我的资料、学习中心。
  - 企业洞察：企业智能中枢、部门数据（仅管理员）。
- 将“管理中心、设置、帮助与反馈”放到侧栏底部的独立工具导航；管理中心内部继续按权限展示治理中心和企业智能管理。
- 保持所有现有页面组件、跳转回调与后端接口不变。
- 保持展开、收起、沉浸三种侧栏模式以及移动端可用性。

## 非目标

- 不合并成果中心与工作成果的数据模型。
- 不调整角色或企业权限策略。
- 不改版本号，不提交或推送 Git。

## 验收标准

- 普通内部用户的主导航最多展示六个一级入口。
- 管理员仍能进入部门数据、治理中心、企业智能管理和帮助与反馈。
- 外部用户看不到企业洞察与管理入口。
- 当前工作域及当前页签都有明确的 `aria-current="page"` 状态。
- 原“4.0 编辑 Demo”不出现在任何导航区域。
- 相关组件测试、类型检查和前端全量测试通过，`git diff --check` 无格式错误。

## 验证计划

1. 先补充导航结构、页签切换和角色可见性测试，并确认旧实现下失败。
2. 实现导航信息架构和响应式样式。
3. 更新依赖旧扁平菜单的现有测试与端到端定位器。
4. 运行定向 Vitest、桌面端类型检查、前端全量测试和 `git diff --check`。

## 实施结果

- 左侧一级主导航已收敛为六个工作域；外部角色继续隐藏“企业洞察”。
- 原业务页面已迁移到工作区顶部的上下文页签，没有删除页面或改变页面间跳转。
- 管理中心、设置、帮助与反馈已移动到底部工具区，并保持原角色权限。
- 收起侧栏时，每个入口仍通过 `aria-label` 和 `title` 保留可访问名称与悬浮提示。
- 移动端增加了工作域和上下文页签的换行布局。

## 验证结果

- 定向组件测试：5 个测试文件、47 条用例全部通过。
- Chromium 端到端测试：Agent 市场和工作流两条分组导航路径全部通过。
- 生产构建：`npm -C apps/desktop run build` 通过。
- 格式检查：本次涉及文件的 `git diff --check` 通过。
- 前端全量测试：298 条通过，4 条失败。失败均位于并行开发中的专业成果编辑器测试，原因是草稿读取及租约接口缺少 MSW handler，与本次导航改造无关。
