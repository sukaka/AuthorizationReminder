# 聚信 AI 助手 4.0 正式成果编辑器方案（重新整理版）

> 目标：把“在线编辑”做成成果工作流中的正式能力，不再把原型 Demo 当成产品入口。
>
> 当前结论：本地正式编辑切片已落地并通过桌面端回归；4.0.0 生产发布仍未完成。

## 1. 产品定位

编辑器只出现在以下路径：

```text
成果中心 → 选择专业成果 → 成果详情 → 编辑草稿 → 保存为版本 → 审核/交付
```

不新增“4.0 编辑器”独立菜单，不从聊天页直接创建脱离成果的文档。聊天、专业任务或自动流程生成结果后，只能通过“查看成果/继续编辑”进入同一个成果详情页。

4.0 的编辑事实源仍是 `DeliverableContent.blocks` 和 `DeliverableDraft`。编辑器只负责交互状态，Office 只负责导入、预览、DOCX 转换和导出交付，不作为浏览器内编辑内核，也不引入 Office 容器或实时协同依赖。

## 2. 并发与恢复原则

4.0 不做多人实时共同编辑，但必须解决“两个人同时点编辑”的问题：

1. 打开成果先申请单活 `EditLease`。
2. 第一个成功者获得编辑权；第二个用户进入只读态，看到占用者和预计释放时间。
3. 前端定期 heartbeat；租约失效、网络恢复后 fencing token 失效，页面立即停止输入、上传和保存。
4. 草稿保存同时校验 `draft_revision`、`base_version_uuid`、`content_hash`、`Idempotency-Key` 和 fencing token；冲突返回稳定错误码，不采用静默覆盖或 last-write-wins。
5. 页面关闭、切换成果、保存为版本后主动释放租约；崩溃后由 TTL 回收，其他用户可在规则允许时重新申请。
6. 服务端草稿是恢复来源；本地不长期保存明文正文。自动保存失败时保留内存编辑内容，并显示“重试/刷新/另存副本”操作。

## 3. 编辑器能力范围

### 3.1 本地正式切片已实现

- 标题、段落、表格、图片等顶层块的结构化编辑。
- “插入段落/表格/图片”工具栏；图片支持文件选择和将图片拖入上传区。
- 块拖拽排序：拖动时显示明确的“放在目标块前/后”蓝色插入线，落点可检测，块 ID 保持不变。
- 段落、表格、图片三类块均可参与顶层排序；保留撤销/重做和键盘移动入口。
- 草稿自动保存、版本保存、编辑租约、续租、冲突和 fencing 保护。
- V1/V2 正文通过 `documentBlockAdapter` 归一；旧 V1 成果可读，结构化正文仍是服务端唯一事实源。
- 原有正文 `textarea` 仅保留为隐藏兼容镜像，避免旧自动化/无障碍定位断裂；用户不会看到第二个编辑器。
- 黑/蓝正式配色应用于成果工作台，不使用独立原型的青绿色视觉。

### 3.2 仍需补齐后才可称为“完整编辑器”

- 图片属性面板：替代文本、宽度、对齐、上传失败重试已落地；确定百分比进度仍待媒体接口提供进度回调，当前使用可观测的“不确定处理中”状态，不伪造百分比。
- 表格深度操作：增删行列、列宽调整、相邻单元格横向/纵向合并与拆分、方向键/Home/End 网格导航已落地并有适配层与组件回归；当前只接受规则网格和单跨度相邻单元格，复杂跨行/跨列网格仍需补齐。
- 块级删除的事实/评论/审核锚点影响提示，以及真实块定位滚动与高亮已落地；删除只作用于当前草稿，提交新版本后由版本事实源统一失效锚点。
- 中文 IME 合成期间暂存、纯文本粘贴清洗、区块键盘移动提示、500 块/5 万字本地性能基准已落地；性能基准用于回归门禁，不替代真实浏览器和生产数据压测。
- DOCX 复杂特性支持/降级/拒绝报告的 golden 回归；复杂浮动排版、批注、域、宏不承诺无损往返。

这些是后续本地迭代，不应通过“演示可用”冒充已完成。

## 4. 页面和入口设计

正式成果页保持三栏：

```text
┌────────────┬──────────────────────────────┬─────────────────┐
│ 成果/目录   │ 工具栏 + 块编辑画布           │ 事实/审核/评论/版本 │
│ 章节跳转    │ 段落/表格/图片，可拖拽换序      │ 选中块的证据与状态  │
└────────────┴──────────────────────────────┴─────────────────┘
```

- 左侧目录点击后滚动到真实块并高亮。
- 中间画布是唯一可见编辑区；保存状态、只读原因和版本动作位于工具栏。
- 右侧继续承载事实锚点、评论、审核、版本和导出，不把这些信息搬进 Office。
- 无编辑租约时，插入、拖拽、上传、撤销后的保存动作都禁用，并明确说明“谁在编辑、何时释放”。

## 5. Office 边界

| 能力 | 归属 |
|---|---|
| 浏览器内段落/表格/图片编辑 | 聚信块编辑器 |
| 块拖拽、撤销/重做、键盘移动 | 聚信块编辑器 |
| Office 模板、DOCX 导入解析、预览、导出 | 现有 Office/转换适配层 |
| 图片资产扫描、权限、哈希、引用计数 | 聚信媒体服务 |
| Word Online/OnlyOffice 实时协同 | 4.0 不接入，另立连接器项目 |

导入和导出必须生成支持、降级、拒绝明细；不能识别的复杂内容禁止静默丢失。

## 6. 接口和数据契约

沿用 `/api/ai/deliverables/{id}`：

- `GET/PUT /draft`：读取和自动保存结构化草稿。
- `POST /draft/lease`、`POST /draft/lease/heartbeat`、`DELETE /draft/lease`：编辑租约。
- `POST /draft/commit`：原子创建不可变版本。
- `POST /media`、`POST /media/{id}/complete`、`DELETE /media/{id}`：受控图片资产生命周期。
- `POST /preview`：同一转换器生成只读预览。

所有写请求都必须带权限上下文、revision、fencing token 和幂等键；错误使用稳定错误码（例如 `DELIVERABLE_EDIT_LEASE_CONFLICT`、`DELIVERABLE_DRAFT_CONFLICT`），前端不得吞掉 409。

## 7. 实施顺序

### P0：契约和内核（已完成当前切片）

锁定块 schema、V1/V2 适配、租约/fencing、草稿 revision、DOCX 转换边界和错误码；已补齐中文 IME 合成、纯文本粘贴清洗和非法节点拒绝测试。

### P1：正式编辑闭环（当前切片）

成果上下文入口、结构化块编辑、明确拖拽落点、图片拖入、撤销/重做、自动保存、恢复、只读冲突、保存版本和现有审核/导出链路。

### P2：编辑质量和复杂 Office

图片属性、失败重试、表格基本深度操作、真实块定位、删除影响确认、IME/粘贴清洗、区块键盘提示、表格网格导航和 500 块/5 万字性能基准已进入本地切片；下一步只补齐媒体确定进度回调、复杂跨行/跨列表格，以及 DOCX 支持/降级/拒绝 golden。

### P3：发布准备（用户之前要求最后考虑）

共享数据库迁移、真实登录授权和 Provider、预发布部署、双 Worker/双编辑者故障演练、灰度、回滚、生产监控和真实业务数据验收。未完成 P3，不标记 4.0.0 生产稳定。

## 8. 可检测验收标准

### 本地候选门禁

- 独立 Demo 菜单/路由不可达；成果中心链路可进入编辑器。
- 第二个编辑者稳定收到 409 并进入只读；旧 fencing token 不能写入。
- 段落、表格、图片拖拽前/后落点明确，顺序正确，ID 不变，单次撤销可还原。
- 图片文件拖入上传区可触发既有媒体上传函数；非图片文件被拒绝。
- 草稿自动保存、恢复、显式版本提交和 DOCX 导出回归通过。
- `npm run typecheck`、桌面端全量 Vitest、服务端定向租约测试、`git diff --check` 通过。

### 生产发布门禁

- 数据库 fresh/upgrade/rollback/retry 证据和唯一 migration head。
- 真实授权、Provider、媒体存储、Office 导入导出在预发布可用。
- 双 Worker lease/fencing、网络分区、进程退出、重复事件和未知副作用演练通过。
- 灰度和回滚开关、停止新触发、在途 Run 处置、监控告警和审计证据包齐全。
