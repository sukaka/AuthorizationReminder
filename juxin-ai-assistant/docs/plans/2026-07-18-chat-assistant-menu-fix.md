# 聊天助手切换菜单修复方案

## 症状

- 聊天顶部默认控件显示“自动路由”，符合默认自动化策略。
- 点击“切换助手”后按钮变为“收起”，但手动助手列表不可见。

## 根因假设

- 菜单 DOM 已渲染，测试可以点击 `menuitemradio`。
- `.chat-top-actions` 使用横向滚动，浏览器会将纵向溢出计算为自动滚动并裁剪绝对定位菜单。

## 计划

- 保持自动路由为唯一默认显示，不恢复常驻的助手下拉列表。
- 修正顶部操作条的溢出策略，让二级菜单能在控件下方显示。
- 增加回归断言：点击“切换助手”后手动菜单可见，并能选择助手。
- 跑聊天页测试、类型检查和差异检查。

## 验收标准

- 用户不操作模式控件时仍看到“自动路由”。
- 点击“切换助手”后能看到完整助手列表。
- 选择手动助手后，控件状态更新且下一次请求继续发送对应模式值。

## 实施结果（2026-07-18）

- 已确认根因：顶部操作条的 `overflow-x: auto` 造成纵向溢出被裁剪，菜单虽渲染但不可见。
- 已修复：顶部操作条改为允许溢出，手动助手菜单可以在控件下方显示。
- 已补测：展开按钮的 `aria-expanded` 为 `true`，手动菜单存在且可选择。
- 验证通过：聊天页测试 54 项、TypeScript 类型检查、`git diff --check`。
