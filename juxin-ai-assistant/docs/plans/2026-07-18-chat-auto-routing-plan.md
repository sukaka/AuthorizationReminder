# 聊天自动路由减操作方案

## 目标

让用户进入聊天后只需要输入问题并发送。助手模式默认使用后端自动路由，用户不必先判断应该选择“销售助手、商务助手、交付助手”等；专业助手仍保留，作为低频的手动覆盖入口。

## 范围

- 修改 `apps/desktop/src/pages/ChatPage.tsx` 的模式控件和路由反馈。
- 修改 `apps/desktop/src/theme/tokens.css`，让默认状态更突出、手动选择更隐蔽但可发现。
- 更新 `apps/desktop/tests/chat-page.test.tsx`，覆盖默认自动路由、手动覆盖和低置信度提示。
- 不删除后端助手模式、不改变 `prepareChat` 的请求字段、不修改会话历史语义。

## 交互规则

1. 新会话默认 `auto`，主控件显示“自动路由 · 推荐”。
2. 用户发送问题后，若服务端返回 `effective_mode`，显示“已自动分配：{助手}”。
3. 路由置信度低于 0.55 时只显示非阻断提示“识别信心较低，可切换助手”，不增加确认步骤。
4. 用户点击“切换助手”才展开手动助手列表；选择手动助手后，主控件显示“已固定 · {助手}”，再次选择自动路由即可恢复。
5. 页面刷新和新会话继续以自动路由为默认，历史会话仍按原有模式展示。

## 验收标准

- 不操作模式控件即可发送问题，发送请求的 `mode` 为 `auto`。
- 自动路由结果可见且不打断回答生成。
- 手动选择仍能发送原有模式值。
- 键盘和屏幕阅读器可以发现并操作模式控件。

## 后续建议

- 观察真实问题的路由命中率和低置信度比例，再决定是否调整阈值或补充路由规则。
- 如果培训反馈仍希望完全不看到模式概念，可以继续把“切换助手”移入更多菜单，但不建议删除手动兜底。
