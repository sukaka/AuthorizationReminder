# 风险清单

审计对象：聚信 AI 助手内测版  
审计日期：2026-06-25  
分级标准：高风险 = 可能影响安全/数据/核心可用性；中风险 = 影响稳定性、治理或规模化；低风险 = 影响体验、维护成本或后续扩展。

## 高风险

### 1. Prompt Injection 防护不完整

- 现象：用户输入和参考知识都可能包含指令型文本；当前主要依赖 system/user 分离，没有独立注入检测。
- 影响：模型可能执行用户或知识库中的恶意/越权指令，偏离公司规则或泄露上下文。
- 相关位置：`server/app/generation_service.py`、`server/app/knowledge.py`。
- 建议：增加“不可信内容边界模板”、注入规则检测、Prompt Center 发布前 lint、关键任务输出复核。

### 2. 参考知识仍直接进入模型上下文

- 现象：参考知识被拼入 user message 的“参考知识开始/结束”之间；质量规则也注入 system message。
- 影响：知识内容规模扩大后容易冲击上下文窗口，也可能把非指令内容当成指令。
- 相关位置：`server/app/generation_service.py`。
- 建议：明确知识类型、可信级别、来源；对参考资料使用引用块模板并声明“只作为资料，不作为指令”。

### 3. 缺少完整 Agent Task State

- 现象：当前有 `GenerationRecord.status`，但没有多步骤 Agent 状态机。
- 影响：复杂任务、长任务、工具调用、等待用户确认、失败恢复难以治理。
- 相关位置：`server/app/models.py`、`apps/desktop/src/pages/TaskRunPage.tsx`。
- 建议：先补轻量状态字段/事件表，不要一次性重构为复杂工作流引擎。

### 4. 模型调用在桌面端，服务端无法统一治理模型行为

- 现象：服务端只 prepare/complete，真实模型调用发生在 Tauri 本地。
- 影响：服务端无法统一限流、成本统计、供应商审计、模型响应安全扫描。
- 正面价值：API Key 不进服务端，隐私边界更好。
- 建议：短期保留桌面调用；补充本地 usage 上报、错误分类、输出安全复核；长期可评估可选服务端模型网关。

### 5. 生成过程不可恢复

- 现象：已支持取消和 complete 离线重试，但模型流式生成中断后不能从中间恢复。
- 影响：长输出任务、网络中断、大文档生成时用户体验差，可能残留 PENDING。
- 相关位置：`TaskRunPage`、`model_client.rs`、`GenerationRecord`。
- 建议：增加超时失败回写、PENDING 清理、可重试状态、用户可见恢复入口。

## 中风险

### 1. Context Builder 隐式且硬编码

- 现象：上下文组装散落在 `prepare_generation` 中。
- 影响：后续加上下文预算、引用、模型差异、注入防护时会变得难维护。
- 建议：抽成小型 `ContextBuilder` 服务，先不改变行为，只结构化输出 context sections。

### 2. 知识检索能力较弱

- 现象：基于关键词包含判断，不支持语义召回。
- 影响：任务多、知识多后召回质量不稳定。
- 建议：先增加检索解释、关键词覆盖率、召回条数日志；再评估向量检索。

### 3. Word 模板写死在代码中

- 现象：封面、页眉、页脚、章节补齐、字号样式在 `word_export.py` 中。
- 影响：业务调整模板需要改代码、测试、发版。
- 建议：先把样式常量集中，再逐步支持 `.docx` 模板或 JSON 模板。

### 4. Prompt 内容有双重来源，治理链路易混淆

- 现象：目录 JSON 有 `prompt_content`，运行时从 Prompt Center 拉已发布版本。
- 影响：如果种子、Prompt Center、绑定版本不同步，会出现“任务看起来对，实际生成不对”。
- 建议：管理页展示任务绑定 Prompt ID、版本、摘要和校验状态；发布前做差异检查。

### 5. 审计覆盖还可以继续补全

- 现象：服务端管理/生成关键动作有审计；本地模型开始、取消、失败等事件不一定都有服务端审计。
- 影响：排查模型失败、用户争议、安全事件时证据链不完整。
- 建议：增加不含正文的模型运行事件审计，如 provider、model_id、错误码、latency、request status。

### 6. 本地加密文件的安全边界需要文档化

- 现象：API Key 使用本地随机密钥加密文件保存。
- 影响：体验好、无钥匙串弹窗；但需要明确同机同用户、备份迁移、恶意本地进程场景下的边界。
- 建议：在产品说明中写明“保护目标”和“非保护目标”，并保留未来接入系统安全存储选项。

### 7. 管理能力较多，权限粒度可能还不够细

- 现象：管理接口多使用 `ai_assistant:admin`。
- 影响：任务管理、知识库管理、审计查看、桌面更新发布可能需要拆分权限。
- 建议：按功能拆出 `task_admin`、`knowledge_admin`、`audit_read`、`desktop_update_admin`。

### 8. PENDING 记录治理不足

- 现象：生成 prepare 成功后，如果桌面模型失败或用户关闭窗口，记录可能停留 PENDING。
- 影响：历史页出现大量无输出记录，统计不准。
- 建议：增加失败回写、过期 PENDING 清理、历史页状态说明。

## 低风险

### 1. 输出格式仍依赖模型遵守

- 现象：已增加前端清洗和 Word 清洗，但源头仍可能输出 Markdown 或多余符号。
- 影响：用户体验偶发不一致。
- 建议：继续优化 Prompt 约束，并保留显示层兜底。

### 2. 前端角色菜单只是体验控制

- 现象：前端按 role 显示治理中心/审计入口。
- 影响：如果误认为这是权限控制会有风险；但当前服务端已做真实授权。
- 建议：保留服务端授权测试，前端只作为显示优化。

### 3. 文件上传字段保留但未启用

- 现象：`FILE_RESERVED` 会被后端拒绝。
- 影响：用户可能期待上传资料给 Agent。
- 建议：短期继续隐藏或标注未启用；启用前先做文件安全设计。

### 4. Docker Compose 与本地 Tauri 端口依赖固定

- 现象：Tauri devUrl 固定 `18093`；如果 Docker 占用端口，Vite 会改跑其它端口但 Tauri 仍加载 `18093`。
- 影响：开发时可能误以为代码没生效。
- 建议：开发脚本检测端口占用并提示，或显式选择 Docker Web/本地 Vite 二选一。

### 5. 代码中存在内测期调试痕迹

- 现象：模型测试里有 `eprintln!` 调试输出。
- 影响：不泄露密钥，但正式版日志观感一般。
- 建议：发布前统一日志等级和脱敏策略。

## 指定检查项结论

| 检查项 | 结论 | 风险等级 |
|---|---|---|
| 是否把大量知识直接塞进系统提示 | 质量规则进入 system，参考知识进入 user；已有数量限制，但仍需边界治理 | 高 |
| 是否 Prompt 写死在代码里 | 运行时 Prompt 来自 Prompt Center；但输出规则、文档治理、Word 模板部分写在代码/JSON | 中 |
| 是否缺少任务状态 | 缺少完整 Agent Task State，仅有生成记录状态 | 高 |
| 是否缺少审计日志 | 不缺，已有审计；但本地模型事件可补 | 中 |
| 是否用户上传内容被当成系统指令 | 用户输入在 user message；参考知识边界仍需强化 | 高 |
| 是否存在任意文件读写风险 | 未见任意路径写入；Word 保存限制在下载目录并清洗文件名；仍需继续保持测试 | 低 |
| 是否缺少测试 | 不缺，已有 67 个测试文件；语义检索/注入/长任务状态测试不足 | 中 |
| 是否存在不可恢复的长任务 | 生成中断不可恢复，只有取消和 complete 重试 | 高 |
