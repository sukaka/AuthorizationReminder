# 外部客户智能客服 V2 实施记忆

日期：2026-07-13

## 目标

完成外部客户智能客服的人工接管闭环：机器人无法基于公开资料回答时自动创建工单，通知管理员或工程师；工作人员可认领、回复并关闭工单。企业微信客服将人工答复直接发送回客户；公众号 H5 客户可在同一受控会话内查询人工答复。

## 已确认的基础

- V1 已实现 `ExternalQuestionEvent` 加密事件、公众号 H5 与企业微信客服的公开资料问答、每日外部问题 Top 20。
- `ExternalQuestionEvent` 已预留 `handoff_ticket_id`，无依据场景目前只标记为 `NO_EVIDENCE`，尚未真正建单。
- 企业微信客服已有 `WecomKfClient.send_text`，可向原客户会话发文本；系统内企业微信应用发送器可用于通知内部处理人员。
- 管理端统一使用 `ai_assistant:admin` 鉴权，路由由 `server/app/admin/router.py` 汇总。

## 约束

- 不保存外部客户身份明文；企业微信回信所需的客户 ID 必须密文保存。
- 公众号 H5 不保存可主动推送的 OpenID，人工回复以客户登录后的 H5 查询接口展示。
- 仅做本地代码与测试验证，不进行正式环境微信接口联调。
- 工作区有大量既有未提交修改；只改动本功能涉及文件，不清理或回退其他改动。

## 当前实施计划

1. 新增工单、消息审计模型及 `0040` 迁移。
2. 新增工单服务：幂等建单、认领、加密人工回复、内部通知。
3. 将公众号与企业微信客服无依据路径接入自动转人工。
4. 新增管理员工单接口，以及公众号 H5 查询人工回复接口。
5. 增加定向测试并验证迁移图。

## 已完成（进行中）

- 新增 `ExternalSupportTicket` 与 `ExternalSupportTicketMessage` 模型及 `0040_external_support_tickets` 迁移。
- 新增工单服务，支持按外部问题事件幂等建单、原子认领、加密人工回复和密文客户收件人。
- 公众号 H5 与企业微信客服的无依据路径均已改为建单；企业微信客服保存收件人密文，公众号只通过当前 H5 OAuth 会话读取回复。
- 新增管理员工单列表、认领、回复 API；企业微信客服启用时人工回复尝试直接回原客户会话，失败保留 `FAILED` 投递状态。
- 内部企业微信通知只含工单元数据，不含客户问题明文；客户问题仅在已鉴权后台解密显示。

## 2026-07-13：管理端可视化工单已完成

- 治理中心新增“外部工单”入口和独立工单处理页面。
- 页面支持按状态筛选、刷新、查看客户问题/转人工原因/回复投递记录、认领、回复，以及回复后关闭工单。
- 前端复用既有管理员工单 API，未新增服务端接口、第三方依赖或客户数据暴露范围。
- 新增前端交互测试，覆盖“加载待处理工单 → 认领 → 回复并关闭”。
- 验证已通过：`npm test -- --run tests/governance-pages.test.tsx`（11 项）、`npm run typecheck`、`npm run build`，以及 `git diff --check`。
- 构建仅有 Vite 的主 JS 包超过 500KB 提示，不阻塞构建，也不是本页面引入的新依赖。

## 2026-07-13：外部客服 OWASP LLM 安全加固已完成

- 公众号 H5 与微信客服均启用外部客户专属系统约束：检索资料、用户输入与历史消息均视为不可信数据，不能覆盖系统规则或触发指令执行。
- 外发模型回答增加确定性安全闸门：拦截提示词泄露与敏感字段，限定回答长度，并只附加本次公开资料的去重来源；无法安全发送时退还额度并自动转人工工单。
- 外部模型输出独立限制为 `WECHAT_EXTERNAL_MODEL_MAX_OUTPUT_TOKENS`，默认 1200，且不超过全局模型上限；微信客服单条问题限制为 2000 字。
- 企业微信加密回调改为强制 token、timestamp、nonce、msg_signature 齐全且验签通过，缺签名和无效签名均拒绝；签名比较使用常量时间比较。
- 定向验证通过：`python3 -m pytest tests/test_external_answer_safety.py tests/test_worker_wecom_crypto_polish.py tests/test_context_builder.py tests/test_wechat_external_security.py tests/test_wecom_kf.py`（26 passed），并通过 `python3 -m compileall -q app` 和 `git diff --check`。

## 2026-07-13：通用 OWASP 代码审计与修复（进行中）

- 已将所有检索内容（包含内部资料、个人参考资料、网页内容、历史会话和长期记忆）声明为不可信上下文，禁止其覆盖系统安全与权限规则。
- 聊天预处理令牌改为对用户、随机数和消息内容签名；生成接口会校验签名，阻断客户端篡改预处理消息后直接送入模型。
- 用户自定义模型地址拒绝内网、环回、链路本地与保留 IP，以及带认证信息、查询参数或片段的 URL，降低 SSRF 风险。
- 知识库上传增加流式读取上限；Office 压缩包增加条目数、解压大小和压缩比上限；PDF 页数、提取文本和分块数量均受限，降低上传 DoS/压缩炸弹风险。
- 已完成第一轮 IDOR 与 XSS 静态审计：核心下载、导出、任务、运行记录、工单、模型配置均按当前用户过滤；前端源码未发现 `dangerouslySetInnerHTML`、`innerHTML` 等直接 HTML 注入点。继续复核兼容上传入口和关联写入接口。
