# 统一大屏展示中心设计

## 1. 背景与目标

当前聚信平台包含多个独立业务系统，首期纳入：

- 软件成分分析平台（SCA）
- 培训考试系统
- 授权到期提醒系统

本项目不是在三个系统中分别增加若干统计页面，而是建设一个独立的“统一大屏展示中心”。用户从一个入口选择系统、模板或播放列表，进入全屏展示；三个业务系统继续负责业务处理和数据权限，大屏中心只通过受控 API 获取展示数据。

设计目标：

1. 首期提供 12 套具有明确业务用途和差异化视觉语言的成品模板。
2. 视觉实现优先采用成熟开源插件，不自行重造图表、3D、地图、粒子或拖拽引擎。
3. 支持管理员对成品模板进行有限编排，但不开放任意脚本和完全自由画布。
4. 同时适配标准 16:9 屏幕和超宽拼接屏。
5. 核心能力可完全离线部署，联网时启用可选增强。
6. 统一认证、授权、数据脱敏、审计和故障降级。

## 2. 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 产品形态 | 独立统一大屏中心 |
| 首期范围 | SCA 5 套、培训考试 4 套、提醒系统 3 套，共 12 套 |
| 模板模式 | 精选成品模板 + 有限编排 |
| 部署方式 | 离线可用，联网增强 |
| 屏幕规格 | 16:9 和超宽屏双布局 |
| 视觉引擎 | 开源组件装配引擎 |
| 3D 能力 | 引入 Three.js，每套最多一个核心 3D 场景 |
| 数据接入 | 统一 BFF 调用各系统 API，禁止直连业务数据库 |

## 3. 不做的内容

首期明确不做：

- 完全自由的低代码画布。
- 用户自定义 JavaScript、HTML、SQL 或远程组件。
- 模板直接访问三个业务系统数据库。
- 大屏绕过原系统的数据权限。
- 为了动态效果让所有模块持续运动。
- 手机端大屏编辑；手机只提供模板查看和播放控制的基础适配。
- 跨系统数据仓库和复杂 BI 自助分析。

## 5. 开源插件矩阵

实施前必须再次核对官方仓库、许可证、最新稳定版本和安全公告，并固定精确版本。

| 插件 | 主要职责 | 使用边界 |
| --- | --- | --- |
| Three.js | 3D 地球、空间网络、粒子场、镜头转场 | 每套最多一个核心场景；必须提供非 WebGL 降级 |
| Apache ECharts | 折线、柱状、雷达、仪表盘、排行、地图和动态数据过渡 | 主要二维数据可视化引擎 |
| ECharts GL | 三维柱图、散点、曲面等轻量数据 3D | 不与 Three.js 重复渲染同一核心场景 |
| AntV G6 | 供应链、组织、客户和风险传播图谱 | 用于有明确节点关系的数据 |
| MapLibre GL JS | 在线/离线地图、聚类、飞线和地理钻取 | 离线使用本地瓦片或 GeoJSON |
| GridStack | 有限拖拽、尺寸调整和响应式网格 | 只允许模板声明的区域和尺寸范围 |
| tsParticles | 星空、连线、环境粒子和轻量氛围 | 不承载业务数据，不遮挡可读信息 |
| Anime.js | 页面入场、章节转场、数字和路径动画 | 替代自行编写复杂时间线 |
| DataV Vue3 | 科技边框、装饰、数字翻牌和飞线组件 | 作为装饰层，核心图表仍使用 ECharts/G6 |

若某个 Vue 3 DataV 分支维护状态或许可证不满足要求，则仅替换装饰层，不影响模板数据结构和核心渲染能力。

## 6. Three.js 使用规范

Three.js 用来创造空间感和视觉焦点，不用于展示所有业务信息。

规则：

1. 每套模板最多存在一个常驻 Three.js 场景。
2. 数字、表格、趋势和排名由 ECharts 或普通 DOM 展示。
3. 模型、纹理、着色器和几何体必须复用并显式释放。
4. 页面不可见或模板切换后暂停渲染循环。
5. 提供高、中、低三档特效：
   - 高：完整后处理、阴影、高粒子数。
   - 中：关闭高成本后处理，降低像素比和粒子数。
   - 低：替换为 ECharts、Canvas 或静态背景。
6. 检测 WebGL 不可用、平均帧率过低或显存异常时自动降级。
7. 禁止从外部地址动态加载未审核的模型和纹理。

## 8. 模板与组件模型

模板采用声明式清单，不在数据库中保存可执行代码。

```ts
interface ScreenTemplate {
  id: string
  systemKey: 'sca' | 'train-exam' | 'reminder'
  name: string
  version: number
  themeKey: string
  effectsProfile: 'high' | 'medium' | 'low'
  layouts: {
    widescreen: LayoutDefinition
    ultrawide: LayoutDefinition
  }
  widgets: WidgetDefinition[]
  filters: FilterDefinition[]
  refreshPolicy: RefreshPolicy
}
```

组件只能来自代码内注册的白名单：

```ts
interface WidgetDefinition {
  id: string
  type: RegisteredWidgetType
  dataSourceKey: string
  layoutArea: string
  optional: boolean
  minWidth: number
  minHeight: number
  maxWidth: number
  maxHeight: number
  config: Record<string, JsonValue>
}
```

禁止在 `config` 中保存函数、脚本、SQL、HTML 或未审核 URL。

## 9. 双布局与缩放策略

每套模板提供两份布局定义：

- `widescreen`：设计基准 1920×1080，覆盖 1080p、2K 和 4K 16:9。
- `ultrawide`：设计基准 3840×1080，覆盖 32:9 和 7680×2160 拼接屏。

原则：

1. 同比例屏幕使用等比缩放，不拉伸图表或字体。
2. 4K 使用高分辨率画布，但限制 Three.js 像素比。
3. 超宽布局重新分配信息，而不是把 16:9 横向拉长。
4. 不匹配比例时使用安全区和背景延展。
5. GridStack 编辑分别保存两种布局，避免一个布局调整破坏另一个布局。

## 10. 有限编排

管理员可执行：

- 隐藏或显示标记为 `optional` 的组件。
- 在模板声明的区域内移动组件。
- 在允许范围内调整尺寸。
- 调整筛选条件、刷新频率、主题和特效档位。
- 保存草稿、预览、发布和恢复默认版本。

管理员不可执行：

- 删除标题、核心指标和核心 3D 场景等必需组件。
- 把组件移动到模板未允许的区域。
- 添加任意网络请求、脚本或自定义组件代码。
- 修改组件的数据权限范围。

每次发布生成不可变版本，播放列表固定引用已发布版本。模板回滚不覆盖历史版本。

## 11. 数据 BFF 与数据契约

### 11.1 数据访问

- BFF 通过服务账号或当前用户的受限身份调用业务 API。
- 禁止直接查询 SCA PostgreSQL、培训考试数据库或提醒系统 MySQL 业务表。
- 各 Adapter 负责字段映射，模板不感知业务系统原始响应。

### 11.2 标准响应

```json
{
  "schemaVersion": "1.0",
  "systemKey": "sca",
  "metricKey": "security-overview",
  "generatedAt": "2026-06-10T05:00:00Z",
  "sourceUpdatedAt": "2026-06-10T04:59:45Z",
  "stale": false,
  "status": "ok",
  "data": {}
}
```

状态值：

- `ok`：数据正常。
- `partial`：部分来源不可用。
- `stale`：使用最后成功缓存。
- `empty`：真实空数据。
- `error`：无可用数据。

### 11.3 刷新策略

- 实时类：5 至 15 秒，优先 SSE。
- 运营类：30 至 60 秒。
- 汇报类：1 至 5 分钟。
- 静态目录类：按需刷新或 10 分钟。

BFF 对相同指标请求进行合并和短缓存，避免 12 套模板同时压垮业务系统。重试采用指数退避和熔断。

### 11.4 首期接口补充

现有接口可复用，但需要增加面向大屏的聚合接口，避免前端发出大量细粒度请求。

首期提供：

```text
GET /api/big-screen/catalog
GET /api/big-screen/templates/{templateId}
GET /api/big-screen/playlists
GET /api/big-screen/data/{systemKey}/{metricKey}
GET /api/big-screen/stream/{systemKey}/{metricKey}
POST /api/big-screen/templates/{templateId}/drafts
POST /api/big-screen/templates/{templateId}/publish
POST /api/big-screen/playlists
```

## 12. 产品流程

1. 用户进入统一大屏中心。
2. 选择业务系统。
3. 从缩略图模板库选择大屏。
4. 设置时间范围、项目/部门/客户范围、主题和动画档位。
5. 直接全屏播放，或加入播放列表。
6. 播放列表配置停留时间、顺序和转场。
7. 全屏模式自动隐藏控制栏，通过键盘、遥控器或定时任务控制。

模板卡片显示：

- 缩略图。
- 适用场景。
- 支持的分辨率。
- 特效等级。
- 数据源健康状态。
- 最后更新时间。

## 13. 权限与安全

角色：

- 观看者：查看已授权系统和模板。
- 运营者：创建播放列表、修改筛选条件。
- 设计管理员：有限编排、主题调整和模板发布。
- 系统管理员：数据源、资源包、权限和审计配置。

安全要求：

1. 复用统一登录平台和系统访问授权。
2. BFF 必须再次校验系统、模板和指标权限。
3. 大屏只返回展示所需字段，客户联系人等敏感字段默认脱敏。
4. 所有模板编辑、发布、回滚和播放列表变更记录审计日志。
5. 禁止任意脚本、任意 URL、任意 SQL 和未签名资源包。
6. 外部地图或联网增强必须经过域名白名单。
7. 播放端使用只读短期令牌，不保存业务系统密钥。

## 14. 离线与联网增强

离线部署包包含：

- 所有 npm 依赖和构建产物。
- 中文字体。
- GeoJSON、基础地图瓦片和行政区边界。
- Three.js 模型、纹理和环境贴图。
- 粒子、图标和装饰素材。

联网增强采用适配器：

- 在线地图瓦片和地理编码。
- 可选天气、节假日或网络状态信息。
- 不影响核心指标和模板结构。

网络断开后自动使用本地资源，不出现空白地图或无限加载。

## 15. 故障处理与降级

### 数据源异常

- 保留最后成功数据。
- 明确显示数据时间和异常来源。
- 不用随机数或演示数据填充生产大屏。
- 恢复后平滑更新，避免全部组件同时闪烁。

### WebGL 异常

- Three.js 初始化失败时切换到 ECharts、Canvas 或静态背景。
- 平均帧率持续低于阈值时逐级降低像素比、粒子数、阴影和后处理。
- 低性能模式仍保留核心业务信息。

### 播放异常

- 单个模板失败时记录错误并跳到播放列表下一项。
- 播放列表全部失败时展示系统健康页，不停留在白屏。
- 浏览器恢复可见后重新同步播放进度。

## 16. 性能目标

- 1080p 首屏 3 秒内可用。
- 4K 在目标设备 5 秒内可用。
- 常态动画目标 50 至 60 FPS。
- 低性能模式不低于 30 FPS。
- 不可见模板和图表暂停渲染。
- 24 小时连续播放不存在持续内存增长。
- 同一个指标在 BFF 中合并请求并共享缓存。
- 超宽屏和 4K 不重复下载相同模型、纹理或地图资源。

## 17. 测试与验收

### 功能验收

- 12 套模板均可选择、配置和全屏播放。
- 每套模板都有 16:9 和超宽布局。
- 播放列表支持顺序、停留时间、暂停和恢复。
- 有限编排不能突破模板约束。
- 模板支持草稿、发布、历史版本和恢复默认。

### 数据验收

- 指标与业务系统原始数据抽样一致。
- 权限变化能及时影响大屏数据。
- 空数据、部分失败、过期缓存和完全失败状态均可识别。
- 三个 Adapter 有接口契约测试。

### 视觉验收

- 12 套模板不存在仅换色换标题的重复方案。
- 动画用于表达数据变化、路径和状态。
- 远距离观看时主指标在 3 秒内可识别。
- 1920×1080、3840×1080、3840×2160 和 7680×2160 均无裁切和拉伸。

### 稳定性验收

- 连续播放 24 小时。
- 记录内存、CPU/GPU、帧率、重连和数据失败次数。
- 模拟断网、接口超时、SSE 中断和 WebGL 初始化失败。
- 使用截图基线检查布局漂移。

- 接入 G6、MapLibre、tsParticles、Anime.js 和装饰组件。
- 建立数据源健康、缓存、SSE 和降级机制。

### 阶段三：有限编排与运营能力

- 模板草稿、发布、回滚。
- 播放列表、定时播放和控制端。
- 权限、审计和资源包管理。

### 阶段四：性能与生产验收

- 24 小时稳定性测试。
- 4K、超宽和低性能设备分级测试。
- 离线安装包、安全检查和生产运维文档。

## 19. 成功标准

项目成功不是“能打开 12 个页面”，而是同时满足：

1. 三个系统的数据通过统一中心可靠展示。
2. 12 套模板具有明确业务用途和差异化视觉表达。
3. Three.js 等开源插件带来高质量效果，但不牺牲信息可读性和稳定性。
4. 管理员能安全地调整模板，而不会破坏设计和权限边界。
5. 离线、断网、数据异常和低性能设备都有可用降级方案。
6. 新业务系统可以通过注册 Adapter 和模板清单接入，不需要复制一套大屏应用。
