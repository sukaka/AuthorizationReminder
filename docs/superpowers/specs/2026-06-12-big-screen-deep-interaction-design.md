# 统一大屏模板深度交互设计

## 1. 背景

统一大屏展示中心已经具备 SCA、培训考试和提醒系统共 12 套模板，能够展示实时业务指标、图表、关系图和 Three.js 场景。当前页面以自动播放和被动展示为主，用户将鼠标移入或点击指标后缺少明确反馈，也无法快速理解同一指标在不同组件之间的关系。

本设计为全部模板增加一致的模板内深度交互，让指标卡、图表、排行、状态矩阵、关系图、地图和 3D 场景围绕同一业务指标协同响应，并通过底部分析台提供解释和业务入口。

## 2. 目标

1. 全部 12 套模板使用统一的悬停、点击、锁定、切换和清除交互。
2. 同一指标在当前模板内的多个组件之间产生可解释的联动高亮。
3. 点击指标后打开底部分析台，展示中文指标说明、关联指标和业务入口。
4. 保持大屏的自动刷新、全屏播放、响应式布局和性能降级能力。
5. 复用 ECharts、G6、MapLibre 和 Three.js 的原生事件能力，不重复实现图表交互引擎。

## 3. 不做的内容

- 不做跨模板或跨系统同步选中。
- 不在大屏中直接执行删除、审批、发送、重试等业务写操作。
- 不开放任意 URL、JavaScript、SQL 或用户自定义事件脚本。
- 不强制所有组件对任意指标产生联动；无对应数据的组件保持原状。
- 不使用复杂弹窗遮挡大屏主体内容。
- 不因增加交互而改变现有数据权限和脱敏规则。

## 4. 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 交互深度 | 深度联动 |
| 联动范围 | 当前模板内 |
| 主要交互 | 悬停预览、点击锁定、再次选择切换、空白或 Esc 清除 |
| 反馈载体 | 页面底部联动分析台 |
| 分析台职责 | 指标解释、关联数据、状态提示和业务详情入口 |
| 业务跳转 | 新标签页打开，保留当前大屏状态 |
| 关联规则 | 同指标优先，其次显式配置的关联指标 |
| 无关组件 | 保持正常显示，不强制变暗 |
| 刷新行为 | 指标仍存在则保持锁定，不存在则清除并关闭分析台 |
| 低性能模式 | 只保留颜色、描边和显隐变化 |

## 5. 交互模型

### 5.1 状态

每个正在播放的模板维护一份独立的 `InteractionContext`：

```ts
type InteractionSource =
  | 'metric-card'
  | 'echart'
  | 'ranking'
  | 'status-matrix'
  | 'graph'
  | 'map'
  | 'three'

interface InteractionTarget {
  key: string
  label: string
  value?: number | string
  unit?: string
  group?: string
  relatedKeys: string[]
  source: InteractionSource
  sourceWidgetId: string
  templateId: string
  filters?: Record<string, string | number | boolean>
  detailPath?: string
}

interface InteractionContext {
  hovered: InteractionTarget | null
  locked: InteractionTarget | null
}
```

`hovered` 是临时状态，鼠标离开后恢复；`locked` 是用户明确选择的持久状态。存在 `locked` 时，其他短暂悬停只提供预览，鼠标离开后恢复到锁定指标的联动状态。

### 5.2 状态转换

| 用户动作 | 状态变化 | 页面反馈 |
| --- | --- | --- |
| 移入可交互元素 | 设置 `hovered` | 当前元素和关联元素临时高亮，显示中文提示 |
| 移出元素 | 清除 `hovered` | 无锁定时恢复默认；有锁定时恢复锁定状态 |
| 点击元素 | 设置或切换 `locked` | 联动高亮固定，底部分析台打开或更新 |
| 点击当前已锁定元素 | 保持锁定 | 不反复开关，避免误触 |
| 点击页面空白 | 清除全部状态 | 恢复默认并关闭分析台 |
| 点击分析台关闭按钮 | 清除全部状态 | 恢复默认并关闭分析台 |
| 按 `Esc` | 清除全部状态 | 恢复默认并关闭分析台 |
| 数据刷新 | 重新解析锁定指标 | 指标存在则更新值；不存在则清除状态 |
| 切换模板 | 销毁旧上下文 | 新模板以默认状态开始 |

组件内部的按钮、链接和图表元素点击必须阻止空白区域清除逻辑，防止一次点击同时完成选中和取消。

## 6. 关联规则

每个可交互指标在模板清单中声明元数据：

```ts
interface MetricInteractionDefinition {
  key: string
  label: string
  group: string
  relatedKeys?: string[]
  detailPath?: string
  description?: string
}
```

联动匹配顺序：

1. `key` 完全相同的元素全部联动。
2. 当前指标的 `relatedKeys` 所指向的元素参与次级联动。
3. 同一 `group` 只用于分析台归类，不自动产生联动，避免高亮范围失控。
4. 找不到相同或关联指标的组件保持默认状态。

指标标签、说明和排行名称统一从元数据读取中文文案，组件不得直接把接口字段名作为用户可见文字。

## 7. 前端架构

### 7.1 模板级交互控制器

`ScreenPlayer` 创建并提供模板级交互控制器，负责：

- 保存 `hovered` 和 `locked`。
- 根据模板元数据计算主关联键和次关联键。
- 处理空白点击、`Esc`、模板切换和数据刷新。
- 向所有组件发布当前交互快照。
- 控制底部分析台打开、更新和关闭。
- 构造经过白名单校验的业务详情链接。

控制器采用 Vue `provide/inject` 暴露组合式 API。组件只上报语义化的指标目标，不相互直接调用，避免组件间形成网状依赖。

### 7.2 组件交互协议

所有展示组件遵循相同协议：

```ts
interface InteractiveWidget {
  setHovered(target: InteractionTarget | null): void
  setLocked(target: InteractionTarget | null): void
  clearInteraction(): void
}
```

Vue DOM 组件通过响应式属性实现；ECharts、G6、MapLibre 和 Three.js 适配器可在内部映射为各自引擎的状态或高亮 API。

### 7.3 组件接入

#### 指标卡

- 整张卡片成为可聚焦、可点击元素。
- 悬停时边框增强、轻微上浮并显示中文提示。
- 锁定时保留强调色和选中标识。
- 支持键盘 `Enter`、`Space` 选择和 `Esc` 清除。

#### ECharts

- 使用 ECharts `mouseover`、`mouseout`、`click` 和 `globalout` 事件。
- 使用 `dispatchAction` 的 `highlight`、`downplay`、`showTip` 和 `hideTip` 控制联动。
- 图表数据项携带业务指标 `key`，不依赖显示名称反向推断。
- 折线、柱形、饼图、雷达和地图系列使用同一事件适配器。

#### 排行榜

- 每一行可悬停和点击。
- 主关联显示完整强调色，次关联显示较弱描边。
- 锁定后保持行高亮，排行自动刷新时按 `key` 重新定位。

#### 状态矩阵

- 每个状态格显示中文名称和数值。
- 悬停显示指标说明，点击打开分析台。
- 下方长方形格子明确作为“数据健康矩阵”，颜色代表健康等级，并提供图例和提示，不再作为无说明装饰。

#### G6 关系图

- 监听节点和边的进入、离开、点击事件。
- 节点使用业务指标 `key`，通过 G6 状态切换控制聚焦和关联路径。
- 点击画布空白清除选择。
- 数据刷新后按业务键恢复选中，不保存易变化的内部节点实例。

#### MapLibre 地图

- 地图点位、聚合和区域图层写入业务指标 `key`。
- 悬停使用 feature state 或图层样式变化。
- 点击点位锁定并打开分析台；点击无要素区域清除。
- 地图移动、缩放不触发清除。

#### Three.js 场景

扩展 `ManagedScene`，允许场景注册命中和状态回调：

```ts
interface SceneInteractionHandlers {
  onHover(target: InteractionTarget | null): void
  onSelect(target: InteractionTarget): void
}

interface ManagedScene {
  start(): void
  pause(): void
  resize(width: number, height: number, pixelRatio: number): void
  update(data: unknown): void
  setInteraction?(context: InteractionContext): void
  setInteractionHandlers?(handlers: SceneInteractionHandlers): void
  dispose(): void
}
```

- 使用 Three.js `Raycaster` 完成鼠标命中。
- 可选对象在 `userData` 中保存经过校验的交互目标。
- 悬停只改变材质、光晕或轮廓，不重建几何体。
- 低性能模式关闭射线命中后的镜头运动，只保留颜色反馈。
- 场景销毁时解除指针事件和回调，避免模板切换后残留。

## 8. 底部联动分析台

分析台固定在当前大屏底部，以抽屉形式覆盖少量底部区域，不改变主布局网格。

内容分为四区：

1. 当前指标：中文名称、当前值、单位和状态。
2. 指标解释：业务含义和计算口径的简短说明。
3. 关联指标：展示同模板内最相关的指标及实时值。
4. 业务入口：显示“前往业务系统”按钮。

布局规则：

- 标准 16:9 屏幕高度约 `150px`。
- 超宽屏高度约 `190px`，内容横向展开。
- 小尺寸预览中改为可滚动的紧凑布局。
- 打开和关闭不遮挡顶部标题、模板目录和系统状态。
- 按钮和关闭控件具有清晰焦点样式和中文无障碍标签。

## 9. 业务详情跳转

模板元数据只允许配置相对业务路径，前端根据 `systemKey` 从受信任配置中取得业务系统基础地址。

安全规则：

1. `detailPath` 必须匹配当前系统的路径白名单。
2. 禁止协议相对地址、外部域名、`javascript:` 和数据 URL。
3. 新标签页通过 `window.open` 打开，并设置 `noopener,noreferrer`。
4. 查询参数只携带非敏感上下文，例如指标键、时间范围、项目公开标识和筛选类别。
5. 不在 URL 中携带令牌、用户信息、客户隐私数据或完整接口响应。
6. 无权限或无有效业务路径时隐藏入口，不展示无效按钮。

## 10. 动效与性能

### 10.1 标准动效

- 悬停反馈：`160ms` 至 `220ms`，使用边框、颜色、透明度和轻微位移。
- 分析台打开：`280ms` 至 `360ms`，从底部平滑进入，不使用弹跳效果。
- 联动元素不连续闪烁，不增加持续旋转或高频粒子。
- 锁定状态优先于自动轮播动画，避免视觉竞争。

### 10.2 性能档位

| 档位 | 交互效果 |
| --- | --- |
| 高 | 完整联动、阴影、光晕、路径和适度镜头聚焦 |
| 中 | 保留联动和分析台，降低阴影、光晕、粒子和镜头运动 |
| 低 | 只保留颜色、描边、提示和分析台显隐 |

现有帧率检测触发性能降级后，交互控制器将档位同步给各组件。用户启用 `prefers-reduced-motion` 时直接使用低运动方案，不执行上浮、镜头移动和复杂过渡。

## 11. 数据刷新与异常处理

- 自动刷新不清除用户锁定。
- 刷新后使用业务指标 `key` 重新查找目标，并更新分析台中的值和状态。
- 目标消失、权限变化或数据源切换后清除锁定并关闭分析台。
- 某个组件交互适配失败时只禁用该组件交互，不影响模板其他区域和数据刷新。
- 业务入口配置无效时记录前端诊断信息并隐藏按钮，不尝试打开地址。
- ECharts、G6、MapLibre 或 Three.js 不可用时，降级组件继续接受模板级状态，至少保留 DOM 指标卡和分析台交互。

## 12. 模板接入范围

首期 12 套模板全部配置指标元数据：

- SCA 01 至 SCA 05：项目、组件、漏洞、许可证、扫描任务、治理成效等。
- TRAIN 01 至 TRAIN 04：课程、题目、考试、通过率、组织、证书、异常会话等。
- REMIND 01 至 REMIND 03：到期、提醒、触达、渠道、客户、销售和续费机会等。

每套模板至少满足：

1. 四个核心指标卡可悬停和锁定。
2. 至少一个主图表与指标卡联动。
3. 排行榜或状态矩阵参与联动。
4. 有 3D、关系图或地图的模板，其核心场景可命中并选择业务对象。
5. 至少一个合法业务详情入口；确无详情页的指标可不提供入口。
6. 所有可见交互文字均为中文。

## 13. 测试与验收

### 13.1 单元测试

- 悬停进入和离开时状态正确恢复。
- 点击可锁定、切换，点击空白、关闭按钮和 `Esc` 可清除。
- 同键和 `relatedKeys` 的匹配顺序正确。
- 无对应指标的组件不被错误弱化。
- 数据刷新保留或清除锁定符合规则。
- 详情路径白名单、查询参数过滤和新标签页安全参数正确。
- 高、中、低性能档及减少动态效果偏好正确生效。

### 13.2 组件测试

- 指标卡支持鼠标和键盘操作。
- ECharts 事件可驱动控制器，控制器也可反向调用图表高亮。
- G6、MapLibre 和 Three.js 的事件在销毁后不再触发。
- 分析台在 16:9、超宽屏和预览尺寸下不遮挡关键内容。

### 13.3 浏览器验收

逐一打开 12 套模板，使用真实数据验证：

1. 页面无未登录时展示假数据的问题。
2. 悬停、锁定、切换、清除和分析台行为一致。
3. 中文标签、提示、排行和状态矩阵无接口字段名泄漏。
4. 自动刷新后选中状态稳定。
5. 业务链接打开正确系统和页面，原大屏状态保留。
6. 高、中、低性能模式均可操作。
7. 控制台无未处理异常、重复事件监听或 WebGL 资源泄漏。

## 14. 实施顺序

1. 增加交互类型、模板指标元数据和模板级控制器。
2. 实现底部联动分析台和安全业务跳转。
3. 接入指标卡、排行和状态矩阵。
4. 接入 ECharts、G6 和 MapLibre。
5. 扩展 Three.js 场景协议并接入射线命中。
6. 为 12 套模板补齐中文元数据、关联关系和详情路径。
7. 完成自动化测试、逐模板浏览器验收和性能降级验证。
