# Prompt Library Navigation Design

## Goal

提示词中心增加三级分类、提示词创建/列表二级菜单、按“部门 -> 分类 -> 提示词”浏览，以及个人收藏入口。

## Scope

- 分类从部门下一级分类扩展为最多三级：一级分类、二级分类、三级分类。
- 提示词库菜单下拆分为“提示词创建”和“提示词列表”。
- 提示词列表默认展示部门；进入部门后展示分类树；点击分类后展示该分类及子分类下的提示词。
- 提示词行内提供编辑、删除、收藏/取消收藏。
- 一级菜单增加“我的收藏”，只展示当前登录用户收藏的提示词。

## Data Model

- `pc_categories` 增加 `parent_id` 和 `level`。
- `pc_prompt_favorites` 保存 `user_id + prompt_id`，同一用户对同一提示词只能收藏一次。
- 老分类默认作为一级分类保留，后续可在分类管理中补齐下级分类。

## Backend

- 分类保存接口支持 `parent_id`，服务层根据父分类自动计算 `level`，并限制最多三级。
- 提示词列表支持 `category_id` 时包含该分类的所有下级分类。
- 新增收藏接口：
  - `POST /prompts/:id/favorite`
  - `DELETE /prompts/:id/favorite`
  - `GET /favorites`
- 审计日志记录收藏、取消收藏、归档删除。

## Frontend

- 侧边栏保留现有视觉风格，提示词库下展示两个二级菜单。
- “提示词创建”显示表单和三级分类选择。
- “提示词列表”使用三段式布局：部门卡片、分类树、提示词列表。
- “我的收藏”复用提示词列表行组件，仅展示个人收藏。

## Testing

- 后端测试覆盖分类层级、分类含子级筛选、收藏/取消收藏。
- 前端源码测试覆盖二级菜单、三级分类文案、收藏菜单和行内操作。
- 保留现有权限规则：只有部门负责人可以创建、编辑、回滚提示词；归档删除沿用发布权限。
