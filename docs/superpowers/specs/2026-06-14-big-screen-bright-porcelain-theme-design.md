# 统一大屏明亮白色主题设计

## 1. 背景

统一大屏展示中心当前 12 套模板采用深棕黑背景、金色或红绿色强调色。深色方案具有较强氛围感，但在办公室、展厅和白天环境中容易显得压抑，细文字、网格线和低亮度数据也不够清晰。

本设计将全部模板升级为已确认的“云端白瓷”视觉方向：暖白背景、浅蓝网格、深蓝文字、青蓝主数据、薄荷绿正常状态、琥珀黄关注状态、珊瑚红告警状态。保留现有科技线框、动态轨道、粒子、图表动画和模板交互，不改变数据结构、布局和业务行为。

## 2. 目标

1. 全部 12 套模板使用统一的明亮白色视觉基础。
2. SCA、培训考试和提醒系统在统一基础上保留可辨识的系统强调色。
3. ECharts、ECharts GL、Three.js、G6、MapLibre、DataV 和粒子效果完整适配浅色背景。
4. 保留现有模板布局、数据接口、交互联动、性能档位和 WebGL 降级能力。
5. 文字、图表、状态和交互反馈在常见大屏亮度与办公显示器上保持清晰。
6. 通过主题令牌集中控制颜色，减少组件中的硬编码颜色。

## 3. 不做的内容

- 不重新设计 12 套模板的信息架构和网格布局。
- 不更换现有可视化插件。
- 不增加暗色/亮色手动切换入口；本次直接将播放大屏升级为明亮主题。
- 不修改数据接口、指标定义和权限模型。
- 不为每套模板建立完全独立的配色系统。
- 不用纯白大面积铺底、玻璃拟态或高强度霓虹光效。
- 不为了装饰增加新的图片、外部字体或网络资源。

## 4. 候选方向与结论

### 4.1 方案 A：云端白瓷

暖白底色配浅蓝灰网格，主数据使用青蓝色，状态使用薄荷绿、琥珀黄和珊瑚红。面板采用轻边框、局部切角和低强度投影。

优点：

- 白天、办公室和展厅环境可读性最好。
- 与现有科技线框、轨道和图表语言兼容。
- 三个系统可以通过强调色形成差异，不会破坏统一性。

风险：

- 需要完整调整图表、地图和 3D 材质；只改背景会产生视觉割裂。

### 4.2 方案 B：银灰工业

冷灰背景、深蓝黑文字、少量橙色状态强调，整体更偏设备控制台。

优点：

- 稳重、专业，长时间观看不刺眼。

风险：

- 明亮程度有限，和用户要求的白色背景仍有距离。

### 4.3 方案 C：极简报表白

纯净白底、弱装饰、传统图表和较少动效。

优点：

- 信息清晰，开发和维护成本最低。

风险：

- 会削弱大屏的科技感、动态效果和展示冲击力。

最终选择方案 A“云端白瓷”。它在明亮、好看和科技感之间最平衡，并已通过效果图确认。

## 5. 设计原则

### 5.1 白而不空

画布使用带轻微蓝绿色相的暖白，不使用纯白。通过浅网格、局部径向色晕和面板层级建立空间感。

### 5.2 亮而不刺

高饱和色只用于关键数据、选中状态、图表主线和告警。大面积背景、边框和辅助文字使用低饱和蓝灰色。

### 5.3 科技感来自结构

继续使用细网格、切角、局部边线、动态轨道和数据流。避免通过大面积霓虹、发光文字或深色背景制造科技感。

### 5.4 状态色语义一致

- 蓝色：主数据、选中和主要操作。
- 青色：实时、关联和数据流。
- 绿色：正常、成功和健康。
- 黄色：关注、待处理和临近阈值。
- 红色：异常、失败和高风险。
- 灰蓝：无数据、不可用和次要信息。

## 6. 主题令牌

主题令牌由 `ScreenPlayer` 根节点提供，所有子组件和引擎适配器从同一来源读取。

```css
.screen-canvas {
  --screen-canvas: #f4f9fc;
  --screen-surface: rgb(255 255 255 / 84%);
  --screen-surface-solid: #fbfdfe;
  --screen-text: #102a43;
  --screen-muted: #688197;
  --screen-line: rgb(35 91 137 / 15%);
  --screen-grid: rgb(49 116 157 / 5.5%);
  --screen-accent: #1976ed;
  --screen-accent-secondary: #18b8c9;
  --screen-signal: #29c58b;
  --screen-warning: #f3ab28;
  --screen-danger: #f0645a;
  --screen-idle: #e6eff4;
  --screen-shadow: rgb(34 92 129 / 9%);
}
```

禁止组件继续新增与主题语义重复的十六进制颜色。第三方引擎需要数值颜色时，由主题适配器把令牌转换为对应格式。

## 7. 系统差异化配色

三个系统共享画布、文字、线框和状态色，只调整主强调色与辅助色。

| 系统 | 主强调色 | 辅助色 | 视觉含义 |
| --- | --- | --- | --- |
| SCA | `#1976ed` 电光蓝 | `#18b8c9` 青色 | 风险洞察、扫描与依赖关系 |
| 培训考试 | `#008b78` 深薄荷绿 | `#35a7d6` 天蓝 | 学习成长、考试运行与能力提升 |
| 提醒系统 | `#e5663f` 暖珊瑚橙 | `#e6a52d` 琥珀黄 | 时间临近、触达和业务机会 |

告警红统一使用 `--screen-danger`，不能把提醒系统主色直接当作故障状态。颜色之外仍通过文字、图标和状态标签区分语义。

## 8. 页面结构

### 8.1 画布

- 外层舞台背景使用浅蓝灰 `#e9f2f7`，用于非标准比例下的安全区。
- 设计画布使用暖白到浅蓝灰的弱渐变。
- 网格尺寸保持当前 `72px` 基准，颜色改为低透明蓝灰。
- 中心核心区域允许使用透明度不高于 `14%` 的青色径向色晕。
- 不使用覆盖全屏的持续闪烁、扫光或高频渐变。

### 8.2 标题区

- 主标题使用深蓝黑，保持当前字号和布局。
- 英文眉题改为蓝灰色。
- 标题下边框使用主题线色。
- 数据源状态改为浅色胶囊标签，正常为绿色，部分可用为黄色，错误为红色。
- 模板目录入口使用当前系统主强调色。

### 8.3 面板

- 面板背景使用半透明白色，但不使用大面积模糊玻璃效果。
- 边框为低透明蓝灰色。
- 左上和右下保留短科技边线，使用主色和辅助色。
- 投影只用于拉开层级，默认透明度不超过 `10%`。
- 悬停时上移 `2px` 至 `4px`，增强边框和投影。
- 锁定状态使用主色描边，不使用大面积实色填充。

## 9. 组件适配

### 9.1 指标卡

- 标签使用蓝灰色，数字使用深蓝黑。
- 趋势、单位和进度条使用系统主色。
- 正向变化标签使用绿色浅底，异常变化使用红色浅底。
- 卡片之间保持留白，不增加彩色图标。

### 9.2 排行榜

- 序号和进度条使用系统主色到辅助色的短渐变。
- 行标题使用蓝灰色，数值使用深蓝黑。
- 悬停行横向移动不超过 `5px`。
- 排名变化可使用绿色或红色小标签，不用持续闪烁。

### 9.3 状态矩阵

- 正常使用绿色浅底，关注使用黄色浅底，异常使用红色浅底，无数据使用蓝灰浅底。
- 每个格子继续显示中文名称和数值。
- 图例、标题和说明文字必须与格子颜色保持一致。
- 颜色深浅表达关注程度，但不能作为唯一状态信息。

### 9.4 ECharts 与 ECharts GL

- 二维坐标轴、分割线和标签改为蓝灰体系。
- 主系列使用系统主色，次系列使用辅助色、绿色、黄色和红色。
- 面积图透明度不高于 `22%`。
- ECharts GL 环境色改为浅色，坐标轴和材质适配白底。
- Tooltip 使用白色实底、深色文字和轻投影。
- WebGL 不可用时继续使用现有纯二维图表降级，降级图表使用同一浅色主题。

### 9.5 Three.js

- 渲染器保持透明背景，由面板提供浅色空间层次。
- 环、核心和粒子改用蓝、青、绿或当前系统强调色。
- 白底下提高几何线条的不透明度，降低泛光面积。
- 选中对象不能变为纯白，应使用更深主色、轮廓或放大反馈。
- 粒子透明度和数量继续受高、中、低性能档位控制。
- WebGL 不可用时的 ECharts 降级必须保持浅色主题。

### 9.6 G6

- 画布使用透明或浅色背景。
- 节点主体使用白底、蓝灰边框；核心节点使用系统主色浅底。
- 边线使用低透明蓝灰，关联路径使用青色，风险路径使用红色。
- 标签使用深色文字，避免白色文字残留。

### 9.7 MapLibre

- 使用浅色离线地图样式，水域、陆地、边界和道路保持低对比度。
- 业务点使用系统主色，描边改为白色。
- 聚合点按数量使用蓝、黄、红的语义梯度。
- 地图覆盖指标卡使用白色背景和深色文字。
- 若现有离线样式无法直接改色，应新增仓库内浅色样式文件，不依赖外部瓦片服务。

### 9.8 DataV 与装饰

- DataV 边框和装饰线颜色改为当前系统主色与浅蓝灰。
- 数字翻牌使用深色数字，不使用浅色数字。
- 装饰动画速度保持现状，不增加高亮频率。
- DataV 不兼容时的 CSS 降级样式与正常样式保持一致。

### 9.9 粒子和入场动画

- 粒子使用蓝、青和低透明绿色，不使用金色与红色混合背景粒子。
- 粒子仅作为核心区域环境层，不遮挡文字和交互。
- 页面首次进入采用一次错峰淡入和轻微上移。
- 持续动画只保留数据流、轨道和必要状态，不让所有面板同时运动。

### 9.10 联动分析台与播放列表

- 联动分析台改为白色实底、深色文字、主题描边。
- 主按钮使用系统主色，次按钮使用透明背景。
- 播放列表面板使用浅色主题，并保持与播放画布的层级区分。
- 键盘焦点使用清晰的主题色外轮廓。

## 10. 动效规范

| 场景 | 时长 | 动效 |
| --- | --- | --- |
| 页面入场 | `600ms` 至 `900ms` | 标题、指标卡、核心区域错峰淡入 |
| 卡片悬停 | `180ms` 至 `240ms` | 上移、边框和投影增强 |
| 排行悬停 | `160ms` 至 `220ms` | 横向移动和进度条强调 |
| 图表绘制 | `700ms` 至 `1200ms` | 折线绘制、柱形增长 |
| 分析台开关 | `280ms` 至 `360ms` | 底部平滑进入或退出 |
| 轨道旋转 | `10s` 至 `24s` | 匀速或缓慢变化 |

使用 `prefers-reduced-motion` 或低性能档位时，关闭位移、扫光和持续粒子，仅保留颜色、显隐和基础图表过渡。

## 11. 响应式与双布局

- 1920×1080 保持当前五区域网格。
- 3840×1080 保持当前超宽三列重排方式。
- 白色主题不能通过增加内边距导致现有内容区缩小。
- 2K、4K 和缩放预览中，边框最细保持一个物理像素可见。
- 高 DPI 下限制 WebGL 像素比，避免浅色抗锯齿带来额外性能负担。
- 非标准比例安全区使用浅蓝灰背景，不使用纯黑遮边。

## 12. 可访问性

- 正文与背景对比度至少达到 WCAG AA。
- 大数字、标题和重要状态不能使用低透明文本。
- 图表状态除颜色外必须有中文标签、数值或图例。
- 聚焦、悬停和锁定三种状态需要可区分。
- Tooltip、状态标签和错误提示统一使用中文。
- `prefers-reduced-motion` 下不依赖动画表达状态。

## 13. 实施边界

建议引入独立的主题定义和适配层：

```ts
interface ScreenTheme {
  canvas: string
  surface: string
  text: string
  muted: string
  line: string
  accent: string
  accentSecondary: string
  success: string
  warning: string
  danger: string
}
```

实施规则：

1. `ScreenPlayer` 根据 `systemKey` 设置 CSS 主题令牌。
2. DOM 组件只使用 CSS 令牌。
3. ECharts、G6、MapLibre 和 Three.js 通过主题适配器获取颜色。
4. 模板清单不保存任意颜色值，避免用户配置破坏对比度。
5. 编辑器、模板目录和播放页共享同一主题预览数据。
6. 不改变现有模板数据契约和组件注册协议。

## 14. 测试与验收

### 14.1 单元测试

- 三个系统能解析正确的主题令牌。
- 图表主题适配器返回完整颜色配置。
- Three.js 场景使用主题色且选中状态在白底可见。
- 状态矩阵的正常、关注、异常和无数据样式语义正确。
- WebGL 降级后仍使用浅色二维图表。

### 14.2 组件测试

- 指标卡、排行、状态矩阵、图表和分析台在悬停、锁定和清除时样式正确。
- 数据为空、数值很长和中文标签很长时不溢出。
- 数据源部分可用或不可用时状态标签仍清晰。

### 14.3 视觉回归

对 12 套模板分别生成 1920×1080 截图，至少覆盖：

- 默认状态。
- 有真实或模拟数据状态。
- 悬停与锁定状态。
- 数据源部分可用状态。
- WebGL 降级状态。

另外生成三套代表性超宽截图：

- `sca-01`
- `train-02`
- `remind-03`

截图中不得出现：

- 深棕黑旧背景或旧金色主题残留。
- 白色背景上的浅色文字。
- 暗色 ECharts、G6、地图或 Three.js 独立区域。
- 英文字段名和第三方 WebGL 错误文字。
- 组件边框、图表或状态矩阵内容不可见。

### 14.4 性能验收

- 明亮主题不能增加新的持续渲染循环。
- Three.js、粒子和图表的性能档位保持有效。
- 生产构建通过，主要包体积不能因主题改造显著增加。
- 标准 1080p 高档模式在目标 Chrome 环境中保持流畅。

## 15. 完成标准

1. 12 套模板默认使用“云端白瓷”主题。
2. 三个系统具有可辨识但一致的主题强调色。
3. 所有 DOM 和第三方可视化区域完成浅色适配。
4. 已有动态效果、联动交互和降级能力保持正常。
5. 16:9 与超宽布局通过视觉回归。
6. 不存在旧深色主题和硬编码金色的可见残留。
7. 单元测试、组件测试、类型检查、生产构建和关键 E2E 测试通过。
