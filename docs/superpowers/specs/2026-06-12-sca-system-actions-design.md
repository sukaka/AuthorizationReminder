# SCA 切换系统与退出系统设计

## 1. 背景

软件成分分析平台已经接入聚信统一登录，侧栏底部也会展示“统一登录”和当前用户名、角色，但当前页面没有“切换系统”和“退出系统”入口。用户进入 SCA 后只能手工修改地址返回统一门户，也无法从页面主动注销统一登录会话。

本设计参考文档管理、培训考试、工单等现有系统，在 SCA 侧栏底部补齐统一的系统级操作。

## 2. 目标

1. 在 SCA 侧栏底部提供清晰可见的“切换系统”和“退出系统”按钮。
2. 切换系统时保留统一登录会话，进入门户的系统切换模式。
3. 退出系统时注销统一登录会话，再返回统一登录门户。
4. 注销请求失败时仍返回门户，避免用户停留在无法继续操作的页面。
5. 使用可单元测试的认证辅助模块，不把 URL 构造和注销协议散落在 `App.vue` 中。

## 3. 不做的内容

- 不修改统一登录门户页面。
- 不修改 SCA 后端鉴权或权限模型。
- 不增加退出二次确认弹窗。
- 不增加用户下拉菜单或重做侧栏。
- 不增加新的网络服务、分析埋点或第三方依赖。
- 不将统一登录接口代理到 SCA 后端。

## 4. 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 按钮位置 | 侧栏底部，用户信息下方纵向排列 |
| 切换按钮文案 | 切换系统 |
| 退出按钮文案 | 退出系统 |
| 退出确认 | 不需要二次确认 |
| 退出反馈 | 注销期间按钮禁用并显示“退出中...” |
| 切换目标 | `/portal?system=sca&mode=switch` |
| 退出目标 | 注销后返回统一登录门户 `/portal` |
| 技术组织 | 独立认证辅助模块，`App.vue` 只负责触发和状态 |
| 最终版本 | 设计提交后从 `5.70.12` 实施，功能提交升级到 `5.71.0` |

## 5. 页面布局

保留当前侧栏底部的统一登录状态和用户信息，在其下方增加按钮组：

```text
┌──────────────────────┐
│ 统一登录             │
│ admin / admin        │
│                      │
│ [ 切换系统 ]         │
│ [ 退出系统 ]         │
└──────────────────────┘
```

布局规则：

- 两个按钮占满侧栏底部可用宽度。
- 按钮纵向排列，间距与其他系统侧栏操作区一致。
- “切换系统”使用普通描边样式。
- “退出系统”使用危险文字色，但不使用大面积实色背景。
- 侧栏菜单继续独立滚动，底部用户信息和按钮不随菜单滚走。
- 退出期间禁用退出按钮，防止重复提交；切换按钮保持现有页面级操作语义。

## 6. 门户地址

新增 `portal-auth.js`，集中处理统一门户地址：

1. 优先读取现有 `VITE_SSO_LOGIN_URL`。
2. 如果配置的是完整登录地址，例如 `https://auth.example.com/portal?system=sca`，解析并保留其 `origin`。
3. 未配置时，使用当前页面协议和主机名，端口回退为 `5180`。
4. 生成以下地址：
   - 系统入口：`<portal-origin>/portal?system=sca`
   - 系统切换：`<portal-origin>/portal?system=sca&mode=switch`
   - 登录门户：`<portal-origin>/portal`

不在组件中手工拼接多份 URL，避免不同按钮产生不一致地址。

## 7. 切换系统流程

用户点击“切换系统”后：

1. 不注销当前统一登录会话。
2. 页面跳转到 `/portal?system=sca&mode=switch`。
3. 门户展示当前用户可访问的其他系统。

切换操作不需要加载状态或确认框，因为它只执行站内导航，不产生数据写入。

## 8. 退出系统流程

SCA 前端的 Nginx 将 `/api/` 代理到 SCA API，因此不能使用相对地址 `/api/auth/logout`，否则请求会误发到 SCA 后端。退出流程直接请求统一登录门户基地址：

1. 将退出状态设置为处理中。
2. `GET <portal-origin>/api/auth/csrf`，携带 `credentials: 'include'`。
3. 读取 CSRF token。
4. `POST <portal-origin>/api/auth/logout`，携带统一登录 cookie 和 `X-CSRF-Token`。
5. 无论注销成功、接口失败、响应无法解析或网络异常，都跳转到 `<portal-origin>/portal`。

统一登录服务已经允许 SCA 页面来源并支持凭据型 CORS 请求。前端不记录 token、cookie 或响应体，不在控制台输出认证敏感信息。

## 9. 组件职责

### `src/portal-auth.js`

负责：

- 解析统一登录门户基地址。
- 构造入口、切换和登录门户 URL。
- 按 CSRF 协议调用统一注销。
- 捕获注销异常并返回布尔结果。

该模块不直接操作 Vue 状态，也不强制执行页面跳转，以便单元测试。

### `src/App.vue`

负责：

- 在侧栏底部渲染两个按钮。
- 点击切换按钮时导航到系统切换 URL。
- 维护 `logoutPending` 状态。
- 点击退出按钮时调用注销辅助函数。
- 在 `finally` 中返回统一登录门户。

### `src/styles.css`

负责：

- 底部按钮组的纵向布局。
- 普通按钮和退出按钮的视觉区分。
- 防止底部操作区在菜单滚动时被挤出。

## 10. 错误处理

| 场景 | 行为 |
| --- | --- |
| CSRF 请求成功、注销成功 | 返回统一登录门户 |
| CSRF 请求失败 | 返回统一登录门户 |
| CSRF 响应没有 token | 返回统一登录门户 |
| 注销请求失败 | 返回统一登录门户 |
| 网络异常 | 返回统一登录门户 |
| 用户重复点击退出 | 忽略后续点击，保持“退出中...” |

失败时仍跳转门户是有意的兜底行为。门户会根据实际 cookie 状态决定显示登录页还是已登录系统列表。

## 11. 测试

新增 Node 测试覆盖：

1. 从 `VITE_SSO_LOGIN_URL` 解析门户来源。
2. 未配置时根据当前页面生成本地门户地址。
3. 切换 URL 包含 `system=sca` 和 `mode=switch`。
4. 注销先请求 CSRF，再携带 token 请求 logout。
5. CSRF 失败、token 缺失和网络异常时返回失败，不继续发出错误请求。
6. `App.vue` 包含“切换系统”“退出系统”、退出中状态和对应处理函数。

验证命令：

```bash
node --test sca-platform/frontend/tests/*.test.mjs
npm --prefix sca-platform/frontend run build
```

实现完成后在应用内浏览器验证：

- 两个按钮位于侧栏底部且不随菜单滚动。
- 切换系统进入门户切换模式。
- 退出按钮显示处理中状态并返回门户。

## 12. 版本与提交

设计文档先使用 `docs(sca)` 提交，统一版本从 `5.70.11` 升至 `5.70.12`。本功能属于用户可感知的功能优化，实施完成后使用 `feat(sca)` 提交，统一版本从 `5.70.12` 升至 `5.71.0`。实施期间只暂存 SCA 功能、测试、必要配置和发布说明，不包含当前工作区内其他任务的改动。
