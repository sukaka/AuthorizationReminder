# 聚信 AI 助手本地启动页与自动更新设计规格

**日期：** 2026-06-20
**状态：** 已完成产品方向确认，待书面规格复核
**目标版本：** 平台仓库 `5.89.0`；桌面应用次版本随实施结果确定
**适用平台：** macOS Apple Silicon arm64、Windows 10/11 x64

本规格是对 `2026-06-19-juxin-ai-assistant-design.md` 的增量修订。两份规格冲突时，以本规格为准；具体覆盖旧规格中的“固定远程工作台 URL”“不建设自动更新服务器”和“启动后直接加载远程工作台”约束，其他统一 SSO、本地模型、钥匙串、MySQL、Prompt Center 和权限边界保持不变。

## 1. 背景与目标

当前桌面安装包启动后直接把主 WebView 指向编译时写入的远程工作台地址。当远程地址是占位地址、DNS 不可用、TLS 失败或服务未启动时，WebView 只显示白屏，用户既看不到产品说明，也无法修改地址或判断故障原因。

本次优化把桌面端改成“本地启动壳 + 远程工作台”：

1. 无论网络和远程服务状态如何，应用都先显示本地欢迎/登录页。
2. 登录前可以填写、保存和测试远程工作台 HTTPS 地址。
3. 连接失败必须显示可理解的原因和恢复操作，不能出现无说明白屏。
4. 统一 SSO 登录成功后再打开远程工作台。
5. 应用能从固定更新服务自动检查新版本，向用户显示更新说明并完成下载、校验、安装和重启。
6. 业务服务器地址、更新服务器地址和更新签名公钥必须保持独立信任边界。

## 2. 范围与非范围

### 2.1 本次范围

- 本地打包的欢迎/登录页、产品简介和状态界面。
- 登录前远程地址录入、格式校验、连接测试、保存和修改。
- 本地启动窗口与远程工作台窗口的生命周期管理。
- SSO 跳转、登录完成检测、连接失败回退和退出登录回退。
- 远程页面调用 Tauri 命令时的运行时来源校验。
- 启动检查、定时检查、手动检查、更新提示、下载进度、签名校验、安装和重启。
- macOS arm64 与 Windows x64 的签名更新产物和更新清单。
- 单元、集成、E2E、真实安装包和故障场景验证。

### 2.2 明确不做

- 不在本地启动页建设独立账号密码、验证码、MFA 或本地用户体系。
- 不允许业务服务器下发或替换更新签名公钥。
- 不允许登录前录入 HTTP 公网地址；开发模式仅允许回环地址使用 HTTP。
- 第一版不实现二进制差分补丁。Tauri 更新器下载经过签名的完整更新产物，但用户不需要卸载或重新手动安装。
- 第一版不做后台静默强制升级；发现新版本后由用户确认安装。
- 不在远程服务不可用时提供离线 AI 生成；只允许进入已有的本机草稿/待同步状态入口。

## 3. 方案选择

### 3.1 采用方案：本地启动窗口 + 独立远程工作台窗口

应用启动时只创建本地 `launcher` 窗口，内容来自安装包内的 React 静态资源。用户确认远程地址并点击统一登录后，Tauri 创建 `workspace` 窗口并加载受信任远程 Origin。登录完成后隐藏启动窗口；远程加载失败、退出登录或用户选择“返回连接设置”时，关闭工作台并重新显示启动窗口。

采用两个窗口而不是在同一窗口内直接跳转，原因是：

- 本地错误页永远可用，不依赖远程页面是否成功加载。
- 远程工作台崩溃或白屏时可以直接销毁并重建，不污染本地启动状态。
- 本地更新 UI 与远程业务 UI 可以使用不同的 Tauri 权限。
- SSO 页面、业务页面和本地管理命令的来源边界更清晰。

### 3.2 未采用方案

- **继续直接加载远程页面并增加超时：** 改动最少，但远程页面失效时仍没有可靠的本地恢复入口。
- **把完整工作台打包到本地并只调用远程 API：** 离线 UI 最完整，但现有 SSO 使用站点 Cookie，需要扩展桌面授权协议和跨源会话，超出本次必要范围。
- **允许任意远程页面直接获得全部 Tauri 权限：** 可以快速支持动态地址，但恶意或误配服务器会获得本地模型和设备数据权限，不可接受。

## 4. 窗口与状态模型

### 4.1 `launcher` 本地窗口

`launcher` 是应用启动后的默认窗口，始终由本地资源渲染，包含：

- 聚信 AI 助手名称、图标和一句话简介。
- 八类助手、88 项任务、统一 SSO、本地模型密钥和安全同步的简要说明。
- 远程服务地址输入框。
- “测试连接”和“使用统一登录”按钮。
- 最近一次连接状态及脱敏错误。
- “查看本机草稿/待同步”入口。
- 当前应用版本、“检查更新”和新版本提示。

`launcher` 不显示账号密码输入框。远程地址未通过格式校验时，“测试连接”和“使用统一登录”不可用。

### 4.2 `workspace` 远程窗口

`workspace` 只在用户发起登录后创建：

1. 加载已保存的业务 Origin。
2. 未登录时由现有服务端跳转统一登录门户。
3. 登录成功后回到 AI 助手工作台。
4. 工作台拿到现有 `/api/ai/session` 后，继续用短时本地绑定令牌绑定原生本地用户。
5. 发生主文档加载失败、TLS 失败或连续超时时，原生层关闭 `workspace`，显示 `launcher` 的故障状态。

统一登录门户页面不能调用模型、草稿、队列或更新命令。只有当前保存的业务 Origin 且会话绑定成功后，才能调用业务类原生命令。

### 4.3 启动状态

状态使用显式枚举，不以多个布尔值组合：

- `BOOTING`：读取本地配置和版本信息。
- `NEEDS_SERVER`：没有已保存地址。
- `SERVER_READY`：地址已保存且最近一次检测成功。
- `SERVER_UNREACHABLE`：格式有效但连接失败。
- `AUTHENTICATING`：已打开工作台，正在统一登录。
- `WORKSPACE_READY`：远程工作台已完成会话与本地绑定。
- `UPDATE_AVAILABLE`：存在可安装新版本。
- `UPDATING`：正在下载或安装。
- `UPDATE_FAILED`：更新失败，当前版本仍可继续使用。

## 5. 远程地址管理

### 5.1 地址规则

生产构建只接受满足以下条件的 Origin：

- 协议为 `https`。
- 包含有效主机。
- 不包含用户名、密码、路径、查询参数、片段或通配符。
- 端口可省略或显式指定。
- 保存前统一规范化为 `scheme://host[:port]`，删除尾部斜杠。

开发构建可额外接受 `http://localhost[:port]`、`http://127.0.0.1[:port]` 和 `http://[::1][:port]`。该能力必须由编译期开发标记控制，正式安装包不能通过设置开启。

### 5.2 本地保存

远程 Origin 不是秘密，保存在 Tauri 应用数据目录的版本化 JSON 配置中，采用临时文件写入后原子替换。配置至少包含：

```json
{
  "schemaVersion": 1,
  "serverOrigin": "https://ai.example.com",
  "lastSuccessfulCheckAt": "2026-06-20T12:00:00Z"
}
```

地址变更必须：

1. 显示旧主机和新主机。
2. 提醒用户新服务器将成为本机模型命令和本地数据同步的受信任业务来源。
3. 用户二次确认后清理当前本地 SSO 绑定和当前窗口 Cookie。
4. 保留加密待同步队列，但按原服务器 Origin 隔离，禁止自动同步到新服务器。
5. 模型配置及钥匙串密钥继续保留，不向新业务服务器发送。

### 5.3 连接检测

连接检测由 Rust 原生 HTTP 客户端执行，不依赖 WebView。新增无认证能力发现接口：

```http
GET /api/ai/desktop/bootstrap
```

成功响应：

```json
{
  "product": "juxin-ai-assistant",
  "protocolVersion": 1,
  "authPortalUrl": "https://auth.example.com/portal?system=ai-assistant"
}
```

客户端只接受：

- HTTP 200。
- `product` 精确等于 `juxin-ai-assistant`。
- 支持的 `protocolVersion`。
- `authPortalUrl` 为 HTTPS 且无 URL 用户信息。

检测结果区分 DNS、连接超时、TLS、证书、HTTP 状态、产品不匹配和协议不兼容。UI 显示中文原因，但日志不记录 Cookie、Token、完整响应正文或用户输入内容。

## 6. 动态来源与 Tauri 权限

动态远程地址不能依赖编译时单一 Origin capability。实施时采用“双层授权”：

1. Tauri capability 只让 `workspace` 窗口具备调用候选业务命令的能力，不授予 shell、文件系统、任意 HTTP 或更新公钥修改能力。
2. 每个可由远程页面调用的 Rust 命令在执行前读取调用 WebView 的当前 URL，并与原生配置中保存的 `serverOrigin` 做精确 Origin 比较。
3. 草稿、队列和模型命令还必须校验已验证的本地 SSO 用户绑定。
4. `launcher` 专用的地址、连接检测和更新命令只接受本地应用 Origin。
5. 登录门户和任何跨域重定向页面不通过来源校验，无法调用业务原生命令。

来源比较必须解析 URL 后比较 scheme、规范化 host 和有效端口，禁止使用字符串前缀匹配。

## 7. 统一登录流程

1. 用户在 `launcher` 填写地址并完成连接检测。
2. 点击“使用统一登录”。
3. 原生层保存 Origin，创建 `workspace` 并导航到业务 Origin。
4. 业务服务继续使用现有 Cookie SSO；未登录时跳转统一门户。
5. 登录门户回跳业务 Origin 后，工作台请求 `/api/ai/session`。
6. 会话成功后，工作台用已有 120 秒、固定 audience 的本地绑定令牌调用 `local_session_bind`。
7. 原生层确认调用来源等于受信任 Origin，再向固定的该 Origin 服务验证绑定令牌。
8. 绑定成功后标记 `WORKSPACE_READY` 并隐藏 `launcher`。

401 重新进入统一登录；403 显示无权限页；网络/TLS 错误返回本地启动页。任何失败都必须有“重试”“修改地址”和“返回启动页”之一，不能只留空白页面。

## 8. 自动更新

### 8.1 信任模型

- 更新地址在构建时写入，不能由远程业务服务器或用户输入修改。
- 更新公钥在构建时写入应用，私钥只保存在受保护的发布环境。
- 业务 Origin 与更新 Origin 可以相同，但配置和信任决策保持独立。
- 只有通过 Tauri 签名验证且版本号高于当前版本的产物可以安装。
- 更新失败不能删除当前可运行版本或清理用户数据。

### 8.2 检查策略

- 应用启动后延迟检查一次，不能阻塞欢迎页显示。
- 应用持续运行时每 6 小时检查一次。
- 用户可以在启动页和工作台设置中手动检查。
- 同一次运行中对同一版本点击“稍后提醒”后，24 小时内不重复弹窗；手动检查不受该限制。
- 更新服务不可用时只显示非阻塞状态，不影响登录和工作台。

这里的“服务端推送”定义为：发布服务生成更新清单后，客户端自动周期检查并提示，不要求保持 WebSocket 长连接。

### 8.3 更新提示与安装

发现更新时展示：

- 新版本号。
- 更新说明。
- 下载大小。
- “稍后提醒”和“下载并安装”。

用户确认后：

1. 显示下载进度和可取消状态。
2. 下载完成后执行签名及平台产物校验。
3. 提示即将重启。
4. 安装更新并重启应用。
5. 重启后保留服务器 Origin、模型配置、草稿和待同步队列。

第一版使用 Tauri 官方签名更新包，解决“每次手动下载 DMG/MSI 并重新安装”的问题；它不是二进制差分下载。

### 8.4 更新清单与平台

更新服务按 Tauri 2 兼容格式发布：

- macOS：`darwin-aarch64`。
- Windows：`windows-x86_64`。
- 每个平台包含版本、发布日期、更新说明、签名和 HTTPS 下载 URL。

正式发布必须同时保留：

- macOS Developer ID 签名与 Apple 公证。
- Windows Authenticode 代码签名。
- Tauri 更新签名。

平台代码签名用于操作系统信任，Tauri 更新签名用于应用自身验证，两者不能互相替代。

## 9. UI 设计

### 9.1 欢迎页

采用已确认的双栏原型：

- 左侧为品牌、产品简介和三项安全价值。
- 右侧为远程地址、连接状态和统一登录操作。
- 右上显示非干扰式更新状态。
- 右下显示当前版本和手动检查入口。

界面使用现有语义色彩和主题 token，不引入第二套设计系统。浅色、深色和跟随系统都必须覆盖欢迎页、错误状态和更新弹窗。

### 9.2 错误状态

错误信息由“发生了什么 + 用户能做什么”组成：

- DNS 失败：无法解析服务器地址，建议检查域名或网络。
- TLS/证书失败：服务器证书不受信任或已过期，不提供忽略证书按钮。
- 超时：服务器暂未响应，可重试或修改地址。
- 产品不匹配：该地址不是兼容的聚信 AI 助手服务。
- 协议不兼容：客户端或服务端版本不兼容，提示先更新。

禁止使用空白页、无限加载或只显示技术异常字符串。

## 10. 数据与隐私

- 远程地址、连接时间和更新提醒时间属于设备配置，不进入业务数据库。
- 连接测试不携带 SSO Cookie、模型密钥、草稿或待同步正文。
- 更新检查不携带用户 ID、部门、模型配置或业务使用数据。
- 更新日志只记录版本、阶段、耗时和脱敏错误。
- 地址切换后，本地队列按用户 ID 与服务器 Origin 双重隔离。
- 卸载与升级默认保留应用数据；用户主动清理时继续遵循现有草稿和待同步保护规则。

## 11. 测试策略

### 11.1 TypeScript/Vitest

- 首次启动始终显示本地欢迎页。
- 地址格式和规范化。
- 未检测成功不能登录。
- DNS、TLS、超时、产品不匹配和协议不兼容的中文状态。
- 地址变更确认和队列隔离提示。
- 更新可用、稍后提醒、下载进度、失败和重启提示。
- 浅色、深色和键盘焦点。

### 11.2 Rust

- 配置原子保存和损坏文件恢复。
- 生产 HTTPS 与开发回环 HTTP 规则。
- 连接检测响应解析和错误分类。
- 精确 Origin 比较，覆盖前缀欺骗、默认端口、大小写、用户信息和重定向。
- `launcher` 与 `workspace` 命令来源隔离。
- 地址切换清理绑定并隔离队列。
- 更新地址和公钥不能被业务配置覆盖。
- 更新检查、签名失败、下载取消和失败回滚。

### 11.3 E2E

- 服务器完全不可达时仍能看到欢迎页并修改地址。
- 输入兼容服务后测试连接成功，点击统一登录并进入工作台。
- SSO 401、403、会话过期和服务中断均可回到可操作状态。
- 恶意相似 Origin 无法调用原生命令。
- 模拟更新服务发布新版本后出现提示；稍后提醒和手动检查正确。

### 11.4 真实安装验收

- macOS arm64：断网启动、错误地址、有效地址、Keychain、签名更新、安装重启、Gatekeeper 和公证。
- Windows x64：断网启动、错误地址、有效地址、Credential Manager、MSI/NSIS 安装、签名更新、安装重启和 SmartScreen。
- 更新前后的服务器地址、模型配置、草稿和待同步队列保持完整。

## 12. 迁移与兼容

现有 `1.0.0` 安装包没有本地服务器配置。升级后的首次启动：

1. 如果构建时提供了合法默认业务 Origin，则预填但不自动登录。
2. 如果没有默认 Origin，则显示空输入框和配置说明。
3. 不读取旧二进制中编译的占位地址。
4. 现有模型配置、钥匙串密钥、草稿和待同步队列继续沿用。
5. 更新器只在配置了正式更新地址和公钥的发布构建中启用；开发构建默认禁用。

## 13. 成功标准

以下条件全部满足才算完成：

1. 拔网启动或远程服务宕机时，3 秒内显示完整本地欢迎页，没有白屏。
2. 用户能在登录前录入、测试、保存和修改合法 HTTPS Origin。
3. 非兼容服务、TLS 问题和超时有明确中文错误及恢复操作。
4. 统一 SSO 登录成功后进入工作台，现有 88 项任务和本地模型能力不回退。
5. 未受信任 Origin、登录门户和相似域名不能调用业务原生命令。
6. 新版本发布后，应用自动检测并显示更新提示；用户确认后完成签名验证、安装和重启。
7. 更新失败时当前版本仍可启动，用户数据不丢失。
8. macOS arm64 和 Windows x64 真实安装包均完成断网、登录和更新验收。
