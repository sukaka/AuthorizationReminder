# 统一登录与授权系统（Auth/SSO）用户使用手册

## 1. 系统定位
统一登录系统用于完成三件事：
1. 单点登录（一次登录访问多个系统）。
2. 系统入口聚合（门户列出你有权限进入的系统）。
3. 统一授权（业务系统按角色和动作鉴权）。

## 2. 访问入口
- 登录门户：`http://localhost:5180/portal`
- 直达某系统：`http://localhost:5180/portal?system=<system_key>`
- 切换模式：`http://localhost:5180/portal?mode=switch&system=<system_key>`

常用 `system_key`：
- `reminder`
- `ticketing`
- `inventory`
- `device-flow`
- `sec-impl`
- `cmdb`

## 3. 角色与入口权限
默认角色口径如下（最终以用户 `app_access` 配置为准）：

| 角色 | 默认可访问系统 |
|---|---|
| `admin` | 全部系统 |
| `sysadmin` | `reminder`、`sec-impl` |
| `auditor` | `reminder`、`ticketing`、`cmdb`、`inventory`、`device-flow`、`sec-impl` |

## 4. 登录流程
1. 打开 `http://localhost:5180/portal`。
2. 输入账号和密码（密码框右侧“眼睛”按钮可切换明文/密文）。
3. 若页面显示验证码，输入验证码后提交。
4. 登录成功后：
- 如果 URL 带 `system` 且有权限，会自动跳转目标系统。
- 否则显示“选择系统”卡片，点击“进入”。
5. 会话使用浏览器会话 Cookie，关闭浏览器后需要重新登录。

## 5. 系统切换与退出
### 5.1 切换系统
1. 在任意业务系统点击“切换系统”。
2. 页面进入 `/portal?mode=switch...`。
3. 在门户中选择目标系统进入。

### 5.2 退出登录
1. 在任意业务系统点击“退出登录”。
2. 系统会调用统一登出接口并清理会话。
3. 再访问业务系统时会回到统一登录页。

## 6. 常见问题处理
### 6.1 关闭浏览器后再次访问要求重新登录
这是预期行为。统一登录 Cookie 为会话级，不做持久化“记住登录”。

### 6.2 登录后反复跳转
按顺序检查：
1. 浏览器地址中的主机名保持一致（不要混用 `localhost` 和 `127.0.0.1`）。
2. Cookie 未被浏览器策略拦截（允许本地站点 Cookie）。
3. 清理当前站点缓存后重新登录。
4. 确认系统地址通过门户进入，而不是手工拼错端口。

### 6.3 显示“正在跳转到统一登录页面”不进入系统
通常是会话失效或无权限：
1. 重新登录。
2. 在门户确认是否看得到该系统入口。
3. 联系管理员检查用户 `app_access` 是否包含目标系统键。

### 6.4 看不到某系统入口
说明该系统不在当前账号授权范围。需要管理员在用户管理中配置 `app_access`。

## 7. 安全提示
- 不要在公共环境保存密码。
- 登录后尽量通过系统侧边栏“切换系统/退出登录”进行跳转。
- 审计事件会记录来源 IP、动作和时间，用于追溯。
