# 系统版本规范

本文档定义整套系统的统一版本号规则。后续发布、分支命名、标签命名、发布说明都按本规范执行。

## 1. 标准格式

- 统一格式：`主版本.次版本.修订号`
- 示例：`5.8.0`

## 2. 三段含义

- `主版本`
  - 表示大改版
  - 适用于架构升级、产品形态明显变化、独立系统拆分、权限模型或部署方式发生明显变化
- `次版本`
  - 表示功能优化
  - 适用于新增功能、功能增强、流程优化、页面重做、兼容性增强，但不属于整套系统重构
- `修订号`
  - 表示 Bug 修复
  - 适用于缺陷修复、安全补丁、配置修正、构建与部署问题修复、文档勘误

## 3. 升级规则

### 3.1 升主版本

满足任一条件时，升级第一位：

- 多个系统的核心入口、信息架构或整体交互方式发生重构
- 关键部署模式、鉴权模型、数据模型存在明显不兼容变化
- 产品从“单系统增强”演进为“平台级改版”

升级示例：

- `4.3.7` -> `5.8.0`

### 3.2 升次版本

满足任一条件时，升级第二位，第三位归零：

- 新增独立系统或新模块
- 现有系统增加重要业务能力
- 页面或流程存在可感知的功能优化，但不构成大改版

升级示例：

- `4.0.9` -> `4.1.0`
- `4.2.5` -> `5.8.0`

### 3.3 升修订号

满足任一条件时，升级第三位：

- 修复线上缺陷
- 修复构建、部署、兼容性问题
- 修复安全问题或配置错误
- 修正文档和发布材料中的错误

升级示例：

- `4.1.0` -> `4.1.1`

## 4. 当前口径

- 当前整套系统口径版本：`5.73.2`
- 后续如果做整套后台/门户的大改版，下一次应评估是否进入 `5.8.0`
- 如果只是持续增强当前版本线中的功能，优先升级 `次版本`
- 如果只是修缺陷，优先升级 `修订号`

## 5. 仓库约定

### 5.1 Git 分支

- 版本开发分支使用：`codex/<主版本>.<次版本>.<修订号>`
- 示例：`codex/5.8.0`
- 历史版本分支默认保留，不自动删除，作为回滚锚点使用

### 5.2 Git 标签

- 发布标签使用：`v<主版本>.<次版本>.<修订号>`
- 示例：`v5.8.0`

### 5.3 发布文档

- 发布说明文件放在：`docs/releases/`
- 文件名统一使用：`<主版本>.<次版本>.<修订号>.md`
- 示例：`docs/releases/5.8.0.md`

## 6. 判定优先级

当一次发布同时包含多类变更时，按影响级别最高的那一类决定版本号：

- 大改版优先于功能优化
- 功能优化优先于 Bug 修复

例如：

- 同时包含“独立后台拆分”和“若干修复”时，应按大改版处理
- 同时包含“新增用户导入”和“若干修复”时，应按功能优化处理

## 7. 执行要求

- 每次准备发布前，先判断本次变更属于哪一类
- 先确定版本号，再创建发布说明、分支和标签
- 不允许只改标签不更新发布文档
- 不建议多个子系统各自维护不同的对外版本口径；对外统一以整套系统版本为准

## 8. 提交前缀约定

为支持自动升版，普通提交信息必须使用以下前缀之一：

- `breaking:` / `major:`
  - 触发主版本升级
- `feat:` / `minor:` / `perf:`
  - 触发次版本升级
- `fix:` / `patch:` / `docs:` / `chore:` / `style:` / `refactor:` / `test:` / `build:` / `ci:` / `revert:`
  - 触发修订号升级

补充规则：

- 支持 Conventional Commit 的 scope 写法，例如：`feat(auth): ...`
- 支持 `!` 语法，任何 `type(scope)!:` 或 `type!:` 都按主版本处理
- `fixup! ...`、`squash! ...`、`Merge ...` 这类提交不会触发自动升版

示例：

- `breaking: 重构统一入口与权限模型`
- `feat(auth): 审计中心日志工作台重做`
- `fix(ticketing): 修复导出附件缺失`

## 9. 自动化流程

仓库通过 git hook 自动完成版本对齐：

- `commit-msg`
  - 校验提交前缀是否合法
  - 清理手写的旧版本前缀，避免出现重复的 `[vX.Y.Z]`
- `post-commit`
  - 读取刚提交的 message，自动判断升级级别
  - 同步所有运行时版本文件、bootstrap 默认分支与 README 示例
  - 立即 `git commit --amend`，把版本改动和提交信息一起并入当前 commit
  - 如果当前分支名与旧版本号一致，例如 `codex/4.2.0`，会先自动切到新版本分支 `codex/5.8.0`
  - 旧版本分支会自动保留在上一提交，作为回滚点
  - 自动把新版本分支推送到 `origin`，首次推送自动建立 upstream

最终提交标题格式为：

- `[v<主版本>.<次版本>.<修订号>] <原始提交标题>`
- 示例：`[v5.8.0] feat(auth): 审计中心日志工作台重做`

## 10. 安装方式

首次拉取仓库后执行：

```bash
npm run hooks:install
```

该命令会把仓库本地 `core.hooksPath` 指向 `.githooks`，之后每次 `git commit` 都会自动升版。
