# 统一登录与授权系统（Auth/SSO）需求说明书

## 1. 系统概述
- 系统名称：统一登录与授权系统
- 服务入口：`http://localhost:5180`
- 目标：为各业务系统提供统一登录、统一会话、统一授权判定与系统入口聚合。

## 2. 建设目标
- 消除多系统重复登录，统一用户身份管理。
- 通过 `app_access` 实现系统级授权。
- 通过 `/api/auth/authorize` 实现动作级授权。
- 提供门户页 `/portal` 作为系统跳转入口。

## 3. 业务范围
- 账号登录/登出、会话管理、CSRF 支持。
- 用户鉴权信息下发（`/api/auth/introspect`、`/api/auth/me`）。
- 系统入口聚合（`/api/auth/apps`）。
- 统一授权决策（`/api/auth/authorize`）。

## 4. 角色与权限需求
- `admin`：可访问全部系统与管理能力。
- `sysadmin`：系统管理角色，按配置开放系统入口。
- `auditor`：审计角色，仅访问各系统审计相关能力。
- 需支持内置账号默认权限同步与兜底刷新。

## 5. 功能需求
1. 登录流程
- 支持账号密码登录。
- 登录页密码输入框支持明文/密文切换。
- 登录成功后写入统一 Cookie（`juxin_auth_token`）。

2. 门户聚合
- 门户展示当前用户可访问系统列表。
- 支持按 `system` 参数直达目标系统。
- 需要循环跳转保护与异常回退。

3. 授权接口
- 支持 `system + action + resource` 的细粒度决策。
- 返回结构包含 `allow/reason/constraints`。

4. 会话与安全
- 支持 CSRF Token 获取与校验。
- 登录 Cookie 使用浏览器会话级策略（关闭浏览器后失效）。
- 支持统一登出并清除会话。

## 6. 接口需求
- `GET /api/auth/introspect`
- `POST /api/auth/authorize`
- `GET /api/auth/apps`
- `POST /api/auth/logout`
- `GET /api/auth/csrf`

## 7. 非功能需求
- 鉴权接口响应时延目标：P95 < 300ms（内网）。
- 高可用：授权服务失败时业务系统需返回明确错误，不可误放行。
- 安全：JWT/签名密钥不得使用弱口令。

## 8. 验收标准
- 单账号可在 6 个业务系统无感切换。
- 无 `app_access` 的系统不得在门户展示。
- `auditor` 登录后仅可进入审计功能菜单，不可执行业务写操作。
- 登出后各系统会话统一失效。
- 关闭浏览器后再次访问系统需重新登录。
