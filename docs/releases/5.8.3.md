# 5.8.3

## 本次更新

- 修复提醒系统 `api` 在读取历史加密发送配置时，因旧密文解密失败而直接启动崩溃的问题
- 现在即使旧的 `email.pass`、`sms.accessKeySecret` 等密文无法解开，也只会降级为空值并输出告警
- 避免 `web` 前端访问 `/api/csrf` 时因为后端已崩而出现 `502 / CSRF token invalid`

## 部署说明

- 本次涉及提醒系统后端 `api`
- 更新代码后重建 `api`，建议顺手把 `web` 一起重建，避免浏览器继续命中旧缓存链路

## 验证建议

- 启动后先执行 `curl -i http://localhost:18080/api/csrf`，应返回 `200` 和 token
- 再进入发送配置，点击“保存邮箱配置”不应再出现 `CSRF token invalid`
- 若历史 SMTP 密文已失效，重新保存一次邮箱授权码即可恢复发信
