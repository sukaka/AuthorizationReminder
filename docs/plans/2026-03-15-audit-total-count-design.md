# 2026-03-15 审计总命中数展示设计

## 目标

- 审计中心不再把“条数上限截断后的窗口数”误显示成“总条数”
- 在不重构全部远端审计接口的前提下，尽量展示真实总命中数

## 方案

- 保留现有分页语义：
  - 每页固定 10 条
  - `条数上限` 继续表示本次查询窗口上限
- 后端新增两类元数据：
  - `total`：当前窗口总条数，用于分页
  - `matchedTotal`：总命中数；如果无法精确计算，则返回当前已知下界
  - `matchedTotalIsExact`：是否为精确总数
- 前端统一文案：
  - 精确时：`总命中 386 条`
  - 非精确时：`总命中至少 100 条`
  - 同时明确显示：`当前窗口 100 条`

## 后端规则

- 本地 `operation_logs` 通过 `COUNT(*)` 提供精确总数
- 远端系统优先读取响应中的 `total / total_count / meta.total / pagination.total`
- 若远端未提供总数：
  - 返回条数 `< limit` 时，视为精确总数
  - 返回条数 `= limit` 时，只能确认“至少 limit 条”

## 前端展示

- 顶部统计卡展示“总命中”
- 结果区展示：
  - `总命中`
  - `当前窗口`
  - `覆盖系统`
- 分页摘要明确标注“当前窗口第 X / Y 页”

## 风险与边界

- 跨系统聚合下，部分远端接口仍可能只给出下界而非精确总数
- 当前设计优先避免误导；后续若所有远端统一返回 `total`，即可自然升级为精确总数展示
