# 聚信 AI 助手 Agent Harness

## 目标

让聚信 AI 助手做到：任务有计划、执行有记录、结果有验证、失败可复盘、知识可治理、工具可审计。

## 工作顺序

1. Planner 先拆任务，明确目标、输入、风险、验收标准。
2. Runner 按步骤执行，只调用已登记且允许的工具。
3. Verifier 检查完整度、引用可靠性、格式合规、安全风险。
4. Replayer 复盘关键步骤、失败原因、下一步建议。
5. Governance 把知识、工具、质量和失败案例沉淀进治理闭环。

## 上下文边界

- 公司正式知识、个人资料、当前附件、长期记忆必须分开管理。
- 不把个人资料自动写入公司知识库。
- 不把完整 prompt、密钥、私有资料正文暴露到运行观测数据。
- 知识库没有明确依据时，回答必须说明“当前知识库未找到明确依据”。

## 工具边界

- 工具必须先登记在 `tools/registry.json`。
- 外部写操作默认关闭。
- 不在 registry 中保存密钥。
- 每次工具调用都要能审计：谁调用、何时调用、输入摘要、输出摘要、成功或失败。

## 验收

- 新人只看 `agent-harness/` 能理解 Agent 如何规划、执行、验证、复盘。
- Harness 不绑定具体大模型供应商。
- Harness 文档与业务代码分离提交。
